# Disposable Artifacts trial

This internal harness tests one hosted project in the platform account. It uses invented identities and data. It does not change customer signup or move an existing project. Its outcome belongs in the [pilot change](../../../openspec/changes/artifacts-hosted-pilot/proposal.md).

## Prerequisites and scope

Use Node 22 with `node:sqlite`, ordinary Git, and the pinned dependencies in this folder. Run the contract suite through the existing remote checks before using the harness; the parent `/apply` runs `/save` at task 5.1. Do not run a local build/test gate. The bootstrap controller is an isolated host preview upload; candidate builds and deployments execute remotely.

The retry keeps CI 0.2.0 and Wrangler 4.146.0, but pins Sandbox and its public image to 0.12.5. The npm override ensures CI uses the same corrected SDK. This is the first patch containing [upstream RPC lifecycle fix #799](https://github.com/cloudflare/sandbox-sdk/pull/799): pending RPC method promises keep the connection busy even when its reference counts briefly look idle. The same patch improves startup error reporting and cleanup for containers that were never admitted. Remote checks install the locked pilot dependencies without lifecycle scripts and exercise the actual SDK's pending-call and idle-cleanup behavior. This correction does not establish the cause of an individual live failure; record the retry's before/after outcomes and container absence separately.

Select the platform account explicitly. A mode-0600 JSON credential file under `.scratch/` contains `{"token":"…"}`. The pilot token needs account-scoped Artifacts Read/Write, Worker deployment, Workflows, Containers, D1, R2 and the reads needed to observe those resources. Billing Read is needed for the read-only paid-entitlement preflight. Never widen the existing platform token or change billing. If access is missing, use the established [private key delivery](../../../wiki/development/secrets.md#receive-a-key-through-a-private-link). A separate short-lived pilot token may be created through existing authorized token management; record only its ID, issuer and expiry in `manifest.credentials` with `kind: "management"`.

The controller receives only `CF_TOKEN` and a random 32-byte-or-longer `SESSION_SECRET`, plus bucket-scoped snapshot credentials. `@cloudflare/ci` 0.2.0 pins Sandbox 0.12.1. That Sandbox always snapshots successful runners, even with dependency caching disabled, and requires `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `BACKUP_BUCKET_NAME`. Create a temporary R2 token restricted to the **new cache bucket**, using existing administration. The [R2 token API](https://developers.cloudflare.com/r2/api/tokens/) uses the token ID as the S3 access key and SHA-256 of the token value as the secret. Record its ID/issuer as `kind: "r2"`; keep its values only in a private controller-secrets file and Worker secrets. No account or token administration credential enters the controller or candidate runners. The public `docker.io/cloudflare/sandbox:0.12.1` image needs no Docker on this host.

The run owns a namespace, two repos, three Workers, three D1 databases, two R2 buckets, one Workflow, one named container application and two Durable Object namespaces. Its unique run ID is 6–14 lowercase letters/digits/hyphens; all resource names fit 63 characters. Initial repo-create Git tokens are tracked and revoked before member keys are issued. Namespace deletion is not documented in the current Artifacts API: the explicitly authorized empty-namespace DELETE is a compatibility probe. Preserve a refusal as a metadata leftover and failed cleanup, even if every charged resource is gone.

## Operator commands

Run `node scripts/pilots/artifacts/pilot.mjs OPERATION`. Every operation after `init` requires `--account ACCOUNT --manifest .scratch/artifacts/RUN/manifest.json`. Private credential/token/session/config outputs must remain under `.scratch/`. A failed operation exits nonzero and names its prerequisite; it never fabricates a successful provider result.

| Operation | Additional input | Observable result |
|---|---|---|
| `init` | `--run RUN --account ACCOUNT --manifest FILE` | Private resumable manifest, exact planned inventory, finite bounds. |
| `inventory` | Common account/manifest | Resources that this run may create/delete; no mutation. |
| `preflight` | `--credentials FILE` | Explicit account identity, readable Artifacts and observed Workers Paid entitlement. Failure creates nothing. |
| `provision` | `--credentials FILE` | Manifest-owned namespace/repos/D1/R2/empty Workers with provider IDs; rejects pre-existing names. |
| `seed` | `--credentials FILE` | Distinct staging/production canaries and all real shared memory migrations on disposable D1. |
| `config` | `--owner opaque-subject --owner-email owner@example.com --out FILE` | Trusted controller Wrangler config with exact repo event filter, separate database IDs, one runner. |
| `reserve-pipeline` | `--credentials FILE` | Absent-before-deploy reservations for Workflow/container/DO resources. |
| `receipts` | `--credentials FILE --body FILE` | Records exact pipeline IDs after successful deployment acknowledgment `{run,account,deployedAt}` and fresh provider readbacks. |
| `session` | `--subject SUBJECT --session SIGNING_FILE --out FILE` | Private signed 30-minute test session; signing file contains `{secret,epoch}`. |
| `call ACTION` | `--controller REPORTED_URL --session FILE [--body JSON_FILE] [--out FILE]` | Authenticated controller result; key-bearing results go only to private files. |
| `export` | `--remote CLEAN_HTTPS_URL --mirror NEW_PATH --destination NEW_BARE_PATH` | Mirror restore, identical advertised refs/object IDs and `git fsck --full`. |
| `cleanup` | `--credentials FILE [--admin-credentials FILE]` | Deletes acknowledged manifest resources only, verifies readbacks, reports exact leftovers. |
| `redact` | `--credentials FILE --body RAW_FILE --out FILE` | Evidence with token patterns, auth headers and explicit private token removed. |

`call` permits `state`, `member`, `git-token`, `approve`, `publish`, `remove`, `stop`, `drain-buckets`, and `_memory/join` only on this manifest's controller hostname. `member` takes `{sub,email}`; `git-token` takes `{scope:"read"|"write"}`; `approve` takes `{sha,ref}`; `publish` takes `{id}` from the approval response; `remove` takes `{sub}`; memory join takes only `{machine}`. Identity never comes from a caller-supplied email or GitHub token. `state` omits artifact contents and memory-key hashes; it includes statuses, approvals and safe Git token IDs. Session and Git tokens are intentionally separate.

Provisioning persists a `creating` record before each request. If creation was interrupted after the provider accepted it, resume stops for reconciliation: inspect its private provider receipt, verify the ID and absent-before-create reservation, then record acknowledgment. Never adopt a name just because it matches. Schema seeding is a fresh-database operation; reconcile partial migrations before retrying an interrupted seed.

## Bootstrap and run

Install this folder's locked dependencies without an application build. Produce the private trusted config, reserve pipeline names, and upload the isolated controller using pinned Wrangler with that explicit config/account. Wrangler 4.146.0's event schema uses `filter.repo_name` and `targets: [{type:"workflow",workflow_name:"…"}]`; the build-on-push guide's `repoName`/`target` spelling is rejected by this version. Upload its secrets from the private secrets file, recording safe resource/version receipts. The controller's reported URL, never a constructed guess, is the operator endpoint. Candidate Workers receive only their environment's `DB` binding.

Copy `fixture/` into a scratch repository. Make a first commit, a feature branch and an annotated tag. Issue an owner write Git token through the controller and push using a private Git credential helper/askpass file (tokens must not occur in remote URLs, command arguments or committed files). Artifacts emits `cf.artifacts.repo.pushed`; its exact repository filter starts the Workflow. The SDK checks out the event SHA. The fixture's tests explicitly reject inherited deployment, controller or R2 secrets. Its build reports one base64 module and SHA-256 digest; the trusted pipeline rejects wrong commit evidence and deploys it using a fresh runner and generated allowlisted config in `/tmp`, with `--no-bundle` and no candidate commands.

Use the reported immutable preview to inspect `/identity`, `/canary` and the visible commit. Stage writes must leave the production canary `production-only`. Push a commit adding `FAIL_CHECK` to prove red checks; delete it in the next passing commit. Run direct unapproved `main`, stale approval, outdated production base, duplicate event, read-token push and other-repo fetch cases separately. A stale/base negative case may use the independently tested controller state transition, but **that is not a live provider PASS**: record UNKNOWN unless the behavior was actually exercised through the deployed controller. Stop on repeated provider failures.

The controller checks the authoritative Artifacts branch head when approving and immediately before reserving publication. An unavailable or changed head blocks publication. State transitions are `checking → failed` or `checking → preview-ready → approved → published`. Every push builds a preview only. The owner approval records exact repo/SHA/digest and current production base outside the candidate repo. Publication reserves a durable lock, deploys the stored immutable artifact, and consumes that approval. Failed publication retains the reservation for operator reconciliation rather than blindly repeating a potentially successful deploy. No branch-write permission substitutes for approval. Duplicate events cannot roll the observed branch head backwards.

Only one runner may be active. The controller bounds previews to ten build attempts, no automatic runner retries, and 30 minutes per runner. A passing build uses a check/build runner and a separate trusted deploy runner; approved publications use another runner. These are finite execution bounds, **not a dollar spending cap**. Allow at most ten explicit publication attempts in the run procedure, no indefinite retry loops, and terminate all work before teardown.

## Membership and memory

Issue signed fixture sessions for an opaque owner and member. The owner's session adds the member to the controller-owned roster; create distinct read and write Git tokens and multiple memory keys so removal exercises every issued credential. The memory wrapper authenticates signed join sessions, stores only hashed memory keys, checks live membership on every request and calls the **unchanged** shared `handleMemory` module using the actual six memory migrations. The shared handler supplies author-write checks, shared/personal fact filtering, expiry and transcript permissions. Owner/member facts must use invented emails; cross-identity writes must fail. Test a removed member's original Git keys, memory keys and signed session, then the owner's retained access. Report measured provider propagation separately from immediate roster denial.

Removal immediately marks membership `removing` and advances its session epoch. It revokes every tracked Git token and memory key and observes their provider/database states; any partial failure stays pending. Fresh access is denied throughout; retries finish only outstanding IDs. The owner cannot be removed. The CLI does not mint a session for customers: these simulated principals do **not** test customer authentication, hosted login/team synchronization, all memory clients/hooks, Cloudflare Access session revocation, VM access removal or installers.

## Export, cleanup and decision evidence

Git export includes every advertised ref, branch, tag and reachable history/object identity. Export restores to an independent **local bare Git repository**; it does not prove migration into an actual GitHub repository. Approval records, users, Git/memory keys, infrastructure configuration, D1 facts and pipeline state are service metadata and are excluded. Provide Git authentication through private credential helpers inherited by the export subprocess; remove those helpers after verification.

Before cleanup, export the project and save non-secret controller state. Add every issued controller Git token ID to `manifest.credentials` (with kind `git`), alongside initial, management and R2 IDs. Stop the controller; disable the push event in the trusted config and record the deployment acknowledgment. Inspect/terminate every Workflow instance and read back its terminal status. Call `drain-buckets` after termination to empty **only the controller's two owned buckets** and observe empty lists. Record these readbacks in `manifest.quiesced` as `{controllerStopped:true,triggersDisabled:true,instancesStopped:true}`. The cleanup command requires those receipts before any destructive action. It deletes Workflow/container/Workers, verifies DO namespaces disappear, then deletes repos/buckets/databases and probes empty namespace deletion. A partially created resource without an ID stays listed for reconciliation. Bucket deletion refuses nonempty buckets.

Management-token revocation runs last and only after all resources are verified deleted. R2/management tokens use a **separate existing admin credential** supplied via `--admin-credentials`, not a wider pilot token. Incomplete cleanup retains the management ID for retry, bounded by its original expiry. Never report complete cleanup from a Worker deletion alone. Verify account-level token revocation with the administering credential; save only safe receipts.

`evidence.mjs` defines `caseEvidence`, `adoption` and redaction. Write each case's explicit `PASS`, `FAIL` or `UNKNOWN`, UTC time, SHA where relevant, safe resource IDs, observation and raw redacted evidence pointer in the change's `evidence.md`. PASS requires a real provider observation; contract tests and guessed URLs do not count. UNKNOWN stays UNKNOWN. Adoption requires all named core live cases to pass **and** verified cleanup; any untested core case or leftover means defer.

The report includes provisioning/build/preview/revocation times, actual operation/storage counters where available, and cleanup receipts. Separate observed measurements from estimates and Artifacts from Containers CPU/memory/disk, R2 cache operations/storage, Workflows, D1, Workers and DOs. Do not equate harness REST-call count with all billable Artifacts Git/binding operations.

Pricing checked 2026-10-01: [Artifacts](https://developers.cloudflare.com/artifacts/platform/pricing/) requires Workers Paid and begins storage/operation billing October 14; thereafter 10,000 operations and 1 GB-month are included, with $0.15/1,000 extra operations and $0.50/extra GB-month. [Containers](https://developers.cloudflare.com/containers/platform/pricing/) charges provisioned memory/disk and active CPU separately. For a standard-1 runner, ignoring included allowances and network, estimate `seconds × (4 × $0.0000025 + 0.5 × $0.000020 + 8 × $0.00000007)` = about $0.074 per full 60-minute two-runner preview. Twenty 30-minute preview runners plus ten 30-minute publication runners would be about $1.11 compute/memory/disk alone; image pulls/startup and other services are additional. Recheck pricing and show the exact inventory and a current estimate before the live run. The small trial cannot establish service-scale cost or reliability.
