# Retained revision handoff

The Payload workflow runs `scripts/verify-revision-chain.mjs` after the complete implementation is saved. The `revision-chain` recipe uses the existing collector; collect only the exact saved head and newest matching completed push run/attempt into a fresh owned evidence folder. No browser, staging turn, service credential or paid practice run is needed.

`chain.stdout.txt` records actual source SHAs and instruction digests, the earlier four-part build directive from `da9e789563b0fcaa5a2c174e0fb86bb5bf2de35c`, and current `saved-revision.mjs` decisions. The modeled earlier path breaks the same one-checkpoint/no-intermediate-check assertion that the current path passes. Read checkpoint, push, wait and test counts, source identities, gate reuse and repeated standalone verification decisions. The script uses mock read-only Git/GitHub answers and no real save/push/wait; these are deterministic driver observations, not an agent transcript. Source authoring completion and genuine passing test results stay separate.

`node --test scripts/tests/saved-revision.test.mjs scripts/tests/revision-chain.test.mjs` runs in the ordinary CI suite. It retains staged/unstaged/nonignored-untracked and ignored-file cases, missing/unpushed branches, foreign/malformed identities, superseding same-head attempts, hosted mandatory gates and repair invalidation. Existing `verify-scripts.test.mjs` checks CI-only preparation without staging and scouting without network. Those tests are not rerun by this capture.

Grade the collected raw output against the current scenario. It can show helper identity safety and one modeled unchanged checkpoint, not prove a human-facing preview or future agent compliance. During the real ship, observe the helper against the actual saved receipt and record whether the chain performed a second save. Keep any missing agent-behavior proof explicit. Collector cleanup removes its owned folder; capture creates no source worktree or shared state.
