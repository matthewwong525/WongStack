Why

The page where you paste an API key feels like a developer tool. It opens straight into steps with no word on why the key is needed or whether it's safe, the promise that it stays private sits in small print at the bottom, a key with no guide shows a code name like MAPS_API_KEY, and the timer reads Closes in 480 min. Someone who has never handled a key stops there. The password page and the private form share the same plain look.

What Changes

  1. 1
    A calm start: what it's for, and that it's private. Each private page opens with a small Private link label with a lock, its title, and one plain line saying the key or details stay off the chat. On the key page, the assistant adds one line saying what the key is for, such as So your assistant can read your charges. The steps become numbered circles, the button to the service is step 1, and the paste box is the last step, Paste it here, so the box reads as part of the steps, not a form. The test line says We'll check it with api.stripe.com.

Decisions

  1. assumed2026-10-18

    Assumed: the review page with instructions to input API keys means the private key link's page, because it is the page that carries a service's key steps and a paste box.

  2. asked2026-10-18

    Asked how much the key page should change → chose guided steps: a calm top, numbered steps ending in the paste box, and a big tick when it works.

  3. asked2026-10-18

    Asked whether the page should say what the key is for → chose yes, one line the assistant writes when it sends the link.

  4. asked2026-10-18

    Asked whether the password page and the private form get the same look → chose all three private pages.

  5. assumed2026-10-18

    Assumed: the live view for a robot check keeps its look, because it shows the assistant's browser, takes no typing, and was not named.

  6. assumed2026-10-18

    Assumed: the three pages share one stylesheet, because three copies of one look drift apart.

  7. assumed2026-10-18

    Assumed: Not now replaces both close buttons, because it says the same in two soft words; it still closes the link.

  8. assumed2026-10-18

    Assumed: the time reads as a clock time and turns to minutes only in the last ten, because 480 min reads as pressure and minutes only matter near the end.

  9. assumed2026-10-18

    Assumed: a key with no guide shows a readable name with its code name small beneath, because the code name alone looks technical but whoever set it up still needs it.

  10. assumed2026-10-18

    Assumed: Save and continue keeps its words, because the docs and the assistant's messages name it and it already says what happens.

  11. assumed2026-10-18

    Assumed: the lock is drawn in the page itself, with no picture file or font fetched, because the pages load nothing but their own server's files.

  12. assumed2026-10-18

    Assumed: a minor release, because the pages look and read differently and guides gain a field.

  13. log2026-10-18

    Built: dark colours are set in a dark-mode block, not with light-dark(), because iPhones before iOS 17.5 ignore light-dark() and would show white text on a white button.

  14. assumed2026-10-18

    Assumed: the guide example in the docs keeps the title Stripe key, not Connect Stripe, because the approved sketches and the spec example use it.

  15. assumed2026-10-18

    Assumed: with several keys, the page drops its Saved 1 key. Complete the remaining keys. line, because the 1 of 2 saved count already says it and now announces itself to screen readers.

  16. assumed2026-10-18

    Assumed: the live tunnel check ran from this computer's browser at phone size before saving, closed with Not now and nothing saved, because it tests only this computer's scripts and needs no published copy.

  17. log2026-10-18

    Archived and saved for shipping as 43.4.0 on branch better-api-key-input, after local checks passed and a live key link was checked at phone size.
