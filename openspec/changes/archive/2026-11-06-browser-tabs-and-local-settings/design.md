# Design

## Context

- `browser-server.mjs` `openTab` calls `context.newPage()` for each task. Juggler's `newPage` (`TargetRegistry._newPageInternal`, in Camoufox's `omni.ja`) always calls `Services.ww.openWindow`, so each task gets its own window. There is no driver call for a tab.
- A test on this Mac on 2026-11-06 (`.scratch/tabs.mjs`, a throwaway profile, `--window`) counted on-screen windows through `CGWindowListCopyWindowInfo`: two `newPage` calls gave 2 windows; a `window.open(url, '_blank')` from one of them gave a third page and still 2 windows, with or without `browser.link.open_newwindow` prefs set. The page arrived through `context.on('page')`. A background tab ran ten 10 ms intervals in 114 ms and took a 180 KB screenshot. `document.visibilityState` reads `visible` in every tab (Camoufox spoofs it), so it can not tell tabs from windows.
- `window.open(..., 'noopener')` to `about:blank` gave a page that closed before `goto`. A real address with an opener worked.
- `windowLaunch({ platform, setting })` shows a window only off Linux. On Linux `main()` always starts Xvfb. `windowSetting()` reads `~/.wong-stack/browser-settings.json` (`window`, default on). `checkView()` returns `window` when the running server recorded `window: true`, else `unsupported` off Linux, else the Linux tool check.
- The forwarder always starts (`startForwarder()`), and `launch-config.py` takes `--proxy` and looks up the exit country through it. It came in on 2026-10-09 because UPS loaded only through it.
- Live views: `view.mjs` `front()` raises the page's own X window by xdotool; `browse.mjs front` calls `page.bringToFront()`. The live view resizes the task's page and sets it back.
- The password manager add-on (v50.1.0) was checked only with a stand-in add-on and with no account. `browse.mjs` prints `BROWSE_ADDON=none` at `install`, `status` and a task's first `open` until `addon asked`, `add` or `decline` records a choice; the skill then asks the person. The guard (`refs.mjs` `ADDON_PAGE`, `ADDON_TARGET`) matches every `moz-extension:` page and frame, not one add-on.
- Camoufox's `distribution/policies.json` blocks no add-on install and sets `ExtensionUpdate: false`.

## Goals / Non-Goals

**Goals:** one window with a tab per task; a window by default wherever a screen exists; a Linux link setting; the browser on request; a proxy setting, off by default; settings outside the repo; no password manager question; a real add-on checked in a throwaway browser.

**Non-Goals:** per-task logins or containers; Mac or Windows link mode; restarting a running browser for a setting; the agent using the password manager.

## Decisions

1. **A kept home tab opens every task tab.** At start, the server keeps the context's first page (the window Camoufox opens) as a blank home tab that no task gets. `openTab` opens a task tab by evaluating `window.open(url || 'about:blank', '_blank')` in the home tab and taking the page from `context.waitForEvent('page')`, then sets `opener` to null in it. If the home tab is gone (the person closed it), the next `openTab` makes a new one with `newPage()`: one new window, once. The home tab is never read, closed by the idle reaper, or listed. Alternative: `newPage()` then move the tab with a privileged call; Juggler offers none, so it would need a Camoufox patch.
2. **No tab switch during a turn.** The server keeps the tab of an open person's turn (set by `front` with a `turn` flag from `hand-over.mjs open`, cleared by its end). While one is set, `front` on another tab is refused with `BROWSE_ERROR=the person is using the browser`, and no command calls `bringToFront`. In a live view, the helper re-selects the turn's tab each poll, as it re-raises the window today, so a click on another chat's tab or the home tab goes back; it does not while a page the person or a site opened during the turn is open, since a page can not tell which tab shows.
3. **Window on Linux when a screen exists.** `windowLaunch` gains `screen`: on Linux the window shows when the setting is on and `DISPLAY` or `WAYLAND_DISPLAY` is set at the server's start; else Xvfb starts as today. `browse.mjs window off` on Linux means the link. The server records `window: true` either way it shows one, so `checkView` and `hand-over.mjs` take the window path unchanged. On a window turn, `front()` selects the tab with `bringToFront()` instead of xdotool, so a Linux desktop needs no xdotool.
4. **The browser on request.** On a link computer, *send me the browser* runs `hand-over.mjs open --view --keep-open --note "Here is the browser. Tap Hand back when you're done."` on the chat's tab, with no finish flag needed for `--keep-open`. On a window computer it runs the same command, which takes the window path, holds the turn, and ends when the person says *done* and the agent runs `close`; `browse.mjs front` holds no turn, so another chat's click could switch the window away. The skill drops the *Let me take over opens nothing* rule for this case only; every other route stays.
5. **Proxy setting, off by default.** `browse.mjs proxy [on|off]` writes `proxy` beside `window` in `browser-settings.json` and prints `BROWSE_PROXY=on|off`; with no word it prints the setting. `main()` starts the forwarder and passes `--proxy` only when it is on. The server records `proxy: true|false`. `status` prints both settings, and when the running browser differs from a setting, says it applies at the next start. A refusal's steps for the person name `proxy on` when it is off.
6. **One settings file, outside every repo.** Both settings stay in `~/.wong-stack/browser-settings.json` (mode 600), as `window` does today. No repo file, `.env`, or `.wong-stack.json` holds them.
7. **No password manager question.** `browse.mjs` drops the `BROWSE_ADDON=none` line from `install`, `status` and `open`, and `addons.mjs` drops `asked` and `decline`; `status` prints `BROWSE_ADDON=<name>` only when one was added. An old `password-manager.json` holding only `asked` or `declined` is ignored. The skill drops the offer; `find`, `add`, `open` and `remove` stay for a person who asks.
8. **The real add-on load is a by-hand script.** CI has no network add-on or display. `.scratch/` holds the throwaway checks during the build; the kept check is `scripts/tests/manual/browser-tabs-real.mjs`, run by hand, which starts a throwaway Camoufox with `--window`, opens three task tabs, counts windows on a Mac, clicks and types in a background tab, adds a real add-on from addons.mozilla.org through `addons.mjs`, and checks that its page opens in a task tab and its frames stay out of a snapshot.

9. **On a Mac, hidden until the turn.** The server hides the Camoufox app after launch, and again after a task tab opens if the app shows, with `osascript -l JavaScript` calling `NSRunningApplication.runningApplicationWithProcessIdentifier(<pid>).hide`; no permission is needed (checked 2026-11-06). The process id is the server's own `camoufox` child, so no other Camoufox is touched. `front` with the turn flag unhides it and activates it, then selects the task's tab; macOS may refuse the activation, and the window then shows just behind the person's app. The turn's end (`done`, `closed`, `handed-back`, `timeout`, and a lapsed lease) hides it again, through `front` with `turn: false`. A hidden app takes no mouse click and no `bringToFront` (tried 2026-11-06), so a click, a plain `front`, and a resize unhide it without activating for that step alone, and it hides after the last one. *Show me the browser* is the same on-request turn as *send me the browser* (decision 4). `browse.mjs show` unhides it on this task's tab with no turn, for a finished page, and the next task step from any chat hides it. A failed hide is logged once in `server.log` and ignored: the window then shows, as today. Windows and a Linux desktop are unchanged.

## Risks / Trade-offs

- [A new window flashes before the hide] → one window with tabs means a task tab opens inside the hidden window; only the first start can flash.

- **A background tab may not take every input.** The test showed timers and pictures work; clicks and typing in a background tab are not yet tried. If one fails, that command selects its tab only when no turn is open, and otherwise waits for the turn to end.
- **A live view's resize is per tab.** Playwright sets a viewport per page; in one window it may resize the window for every tab. The build checks it; if it does, the view sets back each tab's size at its end.
- **Proxy off can break a site that needed it**, as UPS did. The refusal steps name `proxy on`, and the CHANGELOG says so.
- **A window on a Linux desktop needs the browser's start to see `DISPLAY`.** A browser started from a service without it uses the link. `status` prints which one it took.
- **An add-on the person adds by hand does not update itself**, since Camoufox's policy turns updates off. `password-manager.md` says to add it again when it stops working.
- **The home tab can be closed by the person.** The next task then opens one new window, once.
