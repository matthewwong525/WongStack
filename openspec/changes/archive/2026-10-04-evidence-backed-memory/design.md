# Design

## Context

See `proposal.md` for the motivation and user choices. The current CLI selects live facts through FTS5, optional tag aliases, and filters in `.agents/skills/memory/scripts/memory.mjs`. Its Worker enforces visibility independently of client-side defaults; `personalFilter` also keeps the admin's normal view narrow. `source <id>` retrieves a transcript only when permitted and available. The digest has a separate role and stays unchanged.

The source repo already has `scripts/tests/fixtures/memory-search-questions.json` and a top-three regression test in `scripts/tests/memory-store.test.mjs`. Those questions primarily test word forms and overlapping terms. A test can pass without demonstrating retrieval of a question that shares no meaningful words with its answer.

Hindsight's [observations](https://hindsight.vectorize.io/developer/observations) and [mental models](https://hindsight.vectorize.io/developer/mental-models) inspired evidence traceability and prepared context. This slice deliberately uses selected original facts, following the user's choice; it does not implement synthesized observations or persistent mental models.

## Goals / Non-Goals

Make search results reusable for a factual brief and reproducible measurement. Keep one access-filtered read path and unchanged human-readable search defaults. Ordinary search and briefs remain model-free. The extension adds an explicitly requested foreground helper, with no app screen, new store, schema, background task, startup injection, or summary cache.

## Decisions

### Share selection, preserve the interface

Extract the existing search selection into `scripts/lib/read-facts.mjs` inside the memory skill, keeping FTS query construction, tag alias expansion, state/branch/change behavior, personal filtering, and ordering together. Add an ID tie-breaker for equal ranks and dates so seeded evaluations are repeatable. Keep the current text output of `search` unchanged and add opt-in `search --json` with a versioned envelope containing selected facts and effective filters. Include fact ID, original body, type, slug, author, creation date, source session ID when present, and state. Do not include credentials, raw object keys, or transcripts. The JSON output uses the same access-filtered results as text, not an independent export query.

Share the selector with `brief <terms> [filters]`. Terms may be omitted when a supported filter specifies the requested scope. An entirely unscoped brief is rejected with guidance to name a topic or filter. Support the existing search filters except `--all`; the brief always selects live facts. The admin's explicit `--everyone` retains its existing meaning, and cannot widen a member's view. Reuse the current trusted store route rather than introducing another data access layer.

Alternative: parse text search lines. Rejected because bodies and formatting are data, not a reliable structured interface; it would make both measurement and citations fragile. Alternative: a separate summary query. Rejected because its filters could drift from search or the store's ownership rules.

### Build the brief without inference or persistence

Add a small pure renderer in `scripts/lib/brief.mjs`. Fetch eight matching facts by default, with an explicit `--limit` up to 20, using search's rank/date ordering. Admit whole entries under the byte budget in that rank order, accounting for group headings and footer, then group the admitted records into open threads, feedback, project decisions, user facts, and references, preserving selection order inside each group. Empty groups disappear. Preserve each fact's original body; a heading is not a new assertion about the facts.

Each entry includes its fact ID, creation date, author, source session ID or an explicit absence, and one shared `source <fact-id>` follow-up instruction. Compact repeated labels and omit unused/default scope fields from the human brief; the structured search envelope stays complete. This is a navigable pointer, not a promise that the reader can open the underlying transcript. Do not join or fetch raw transcripts while building a brief. A visible team fact can have a private source; the existing source command decides access when asked.

Render at most 6,144 UTF-8 bytes, including headers and the footer. Keep whole entries, and reserve room for the footer before accepting another entry. The header shows the topic/filters and generation time. The footer states the requested selection bound (eight by default, maximum twenty) and how many selected entries were omitted to fit; it must not claim to know how many other matching facts exist. An empty successful read says no matching live facts, while unavailable or denied memory is reported as such, never as an empty or complete brief. No cache fallback is added.

Alternative: model-generated synthesis with stored supporting IDs. Still deferred; the new selective helper chooses original facts rather than synthesizing or storing conclusions. Synthesis would require validation of inference, refresh rules, and an additional write/visibility contract. Alternative: rewrite the wiki or replace the digest. Rejected because those surfaces have different ownership and loading rules.

### Evaluate behavior rather than parse prose

Keep every existing regression question and assertion. Extend its fixture with optional classification and separate diagnostic questions; existing consumers must continue to read their original required questions unchanged. Cases use synthetic facts with stable fixture keys, query/filter inputs, expected allowed IDs or an empty answer, and categories: literal/word-form, paraphrase, changed decision, time filter, visibility, and no-answer. Include genuine synonym-only questions, competing distractors, superseded facts, and hidden facts; do not label stemmed matches as semantic success.

Add a meta-only `scripts/evaluate-memory-search.mjs` runner, backed by the existing migrated test store/harness. It reads structured production CLI results and prints per-question target rank, found-in-top-three, unexpected result IDs, and category totals. It supports a JSON report and uses synthetic identifiers only. It must not read this repo's credentials, connect to production, export real memory, or write fixtures to the live store. Clean up its temporary fixture resources on completion or failure.

The report distinguishes `regression` cases, which gate compatibility, from `diagnostic` cases, which expose current semantic limitations. A diagnostic miss is measured, not silently declared passing. Any unexpected hidden or superseded fact, infrastructure failure, or required regression failure fails the run. CI tests exercise the runner and brief through the existing test suite without changing check settings or dropping old cases. Record the initial category results in the change's implementation evidence after `/save`; this plan does not claim measured accuracy yet.

### Select the helper without another classifier

Add an explicit experimental `memory.mjs extract <question> --task <handle> [filters]` read interface. Ordinary `search`, `brief`, and startup/area hooks remain unchanged. The main agent uses its existing task judgment: narrow factual lookups use search; questions spanning decisions, sessions, or topics, or an unsuccessful/ambiguous lookup, may benefit from extract. Do not add a classifier model call. Before live acceptance, document only explicit experimental invocation, with no instruction to use it routinely. After acceptance, give concise selective guidance rather than automatically invoking it for every question.

The caller supplies a concise standalone question, fixed scope filters, and any fact IDs it has already loaded. It does not pass the parent conversation. Each extract request belongs to a locally issued task handle; repeated requests for that handle share the input, output, search, and model-call allowance. The twenty-second deadline is per request; the allowances remain cumulative across requests. The caller obtains one handle per task and reuses it. This bounds the interface under that handle; it cannot enforce a budget across arbitrary new handles, ordinary search/source commands, hooks, or the entire main-agent context.

### Control the model through a read-only broker

Do not reuse the write-capable background capture runner's `agentCommand`. Add a small adapter that launches the calling agent's installed CLI with current authentication and its normal model in an isolated temporary working directory. Disable built-in tools, MCP tools, skills, repository instructions, hooks, and persistent conversations through verified supported options, rather than a prompt alone. Do not assume a read-only filesystem sandbox prevents tool calls. The implementation must demonstrate this for each supported host; unavailable capability or authentication produces a bounded fallback, not a less restricted launch. No new provider credentials or automatic model substitution.

A controller fetches initial candidates through the current permission-enforced store route, then sends a bounded pool to the tool-free model. The model returns a strict versioned JSON response with ordered selected IDs, at most two alternative query strings, and gap codes from a fixed vocabulary. The broker executes only permitted search requests, keeping the caller's original filters immutable, and may perform one more model selection round. Model suggestions cannot change `--everyone`, author/date/type/tag/change/branch scope, invoke commands, read transcripts, or write memory. Treat all fact text as untrusted data. Validate IDs against the authorized candidate pool; reject malformed replies, fabricated IDs, oversized lists, or unexpected fields. No model text streams to the parent agent.

Reuse shared query construction, ordering, tag aliases, and visibility helpers; add a bounded candidate mode instead of copying permission logic. Each candidate search uses a hard SQL row limit of twenty and an application-visible response byte cap of 4,096, with whole-record admission and explicit truncation. At most three candidate searches run. Reject `--all` and the inherited `--state` filtering path on extract, explaining that direct search remains available, because its all-matching-rows scan cannot satisfy this helper's bounded-read contract. Ordinary search/brief retain their existing filter compatibility. A byte cap limits admitted response data, not database work or bytes already transported by the underlying store API; measure those separately if exposed.

Before rendering, re-read the selected IDs in one bounded, permission-enforced batch (at most twenty IDs), excluding any newly superseded or inaccessible fact. This batch is in addition to the three candidate searches; existing access/schema probes are additional measured requests. Do not issue one read per fact. If verification fails or authorization is denied, emit no stale cached facts; say unavailable or denied. If any candidate changed, mark the packet partial and use only the newly verified bodies. Do not automatically fetch a source transcript; the existing separately requested source interface remains unchanged.

### Account for input, output, retries, and time in code

Initial defaults are experimental constants: 12,288 cumulative UTF-8 bytes of application-supplied model input, 3,072 cumulative UTF-8 bytes returned to the parent per task handle, three candidate searches, two model calls, and a twenty-second request deadline covering store reads, model startup, validation, and fallback. Count prompts, question, schema instructions, candidate metadata, repeated candidate text, and all second-round input again. Reserve bytes and calls before executing work. Keep helper replies buffered and individually capped at 4,096 bytes; malformed or over-limit replies stop selection. The host's model completion-token cap is also set when supported; it is not substituted for accounting actual usage.

Use a private ephemeral ledger outside git containing the opaque handle, caller/repo/filter identity, counters, previously returned IDs, and expiry; no credentials, fact bodies, or cached answer authority. Bind handles to current caller/repo identity, fail closed on mismatch or missing state, and serialize/atomically reserve concurrent work to prevent double spending. Handles expire after twenty-four hours; expiry requires explicit creation of a new handle, never silently resets a requested one. No recursive helpers or hidden retries. Repeated results already returned under that handle are omitted and reported as already supplied.

Reserve room for fixed status/footer text before admitting whole original fact entries; headers, sources, omitted-count notes, fallback, and errors all consume the same output allowance. Return code-rendered original bodies plus fact IDs, dates, author, source session when present, and one source-follow-up instruction, in model-selected order. Include a status (`selected`, `partial`, `fallback`, `empty`, `unavailable`, or `denied`) and specific limits/gap codes. When no output budget remains, return no additional stdout packet and signal budget exhaustion by exit status; do not print an unbounded diagnostic into parent context. Detailed usage diagnostics are retained separately in an opt-in private report, not appended automatically to the fact packet.

On model unavailability, invalid output, or timeout, use the authorized deterministic initial selection within the remaining packet budget only if it can be verified while the deadline remains. Reserve time for verification and stop the model early enough to attempt it; if verification cannot complete, report unavailable with no facts. Cancel pending child processes and store requests at the deadline. A limit is a partial result, not evidence that memory has no answer. The fallback adds no model calls and never masks store denial as an empty answer.

These limits bound supplied application text and returned context. CLI/provider system prompts, internal reasoning, and prior main-agent messages are separate. Shorter helper output can still increase total tokens, billing, and wait time. Record provider-reported input/output/cache tokens and model identity when available, and explicitly mark unknown usage rather than estimate tokens from bytes. The ledger is not a global main-agent context manager and cannot remove facts already loaded into that context.

### Compare fact coverage and end-to-end work before recommending the helper

Extend the synthetic runner with direct-eight, direct-twenty, and helper modes. Compare all three under the same 3,072-byte final packet cap using the same fact-entry renderer, question scope, fixture store, and whole-entry policy. Keep the existing uncapped-to-that-size search and brief reports as separately labeled baseline measurements. Add multi-fact questions whose expected set contains every required fact, synonym-only misses, ambiguous distractors, chronological replacements, permission cases, and no-answer questions. Score critical-fact recall and complete expected sets, extra facts, forbidden IDs, bytes supplied/returned, store requests, model calls, actual reported usage, and wall-clock time. Predeclare fixtures and expected facts before inspecting live model results.

Recorded model replies test the protocol, failures, permissions, races, byte limits, and deadlines through remote CI; they do not establish live model retrieval quality or cost. An explicitly enabled remote-host evaluation uses current host authentication and isolated synthetic data only, with no real-store exports. Capture at least twenty executions per mode across the frozen suite to report sample size and p50/p95 wall time; include model/version, repeated-run variance, errors/timeouts, and token-usage availability. Direct modes make no additional model calls. Label this as synthetic end-to-end evidence, not production latency.

To enable selective guidance, require zero forbidden/fabricated results, no loss of existing regression guarantees, no per-case critical-fact loss relative to direct-twenty under the same packet cap, and recovery of both current synonym-only diagnostic misses. Report any direct-eight disadvantage and all extra usage/time; do not gate on an invented speed improvement or claim that eight or these budgets are optimal. If live authentication, host isolation, or quality acceptance is unavailable, keep extract explicitly experimental and leave the promotion task incomplete unless the user agrees to an explicitly experimental delivery. Any revised budget or acceptance rule returns to this plan rather than quietly weakening it.

### Implemented experimental interface and approved delivery

The implementation uses `extract-task [scope filters]` to issue a handle and `extract <question> --task <handle> --agent claude|codex [same filters]` to consume it. `--loaded` accepts up to twenty comma-separated fact IDs; `--usage-report` retains private body-free accounting locally. Concurrent requests hold a private per-handle lock; reservations persist before work and cannot be refunded by retries or crashes. Output exhaustion avoids further work. Missing, expired, busy, or mismatched state emits no fact packet.

Only the installed Claude adapter currently has verified tool-disabling options. It uses safe mode, an empty built-in tool list and MCP configuration, disabled skills/hooks/session persistence, and a temporary working directory. Existing authentication and model selection remain; explicit `--model` is supported. Managed-policy files or configurations that could override isolation are rejected. Codex reports unsupported and follows the same verified deterministic fallback instead of switching hosts. Claude's supported environment controls cap each completion at 2,048 tokens, one turn, and zero API/watchdog retries; returned replies still have their separate 4,096-byte cap. These controls are safeguards, not measured total cost.

Second-round candidate admission also fits the remaining cumulative input allowance, retaining whole records and prioritizing alternative-query hits and previously selected facts. Any reduced candidate pool is visibly partial. Final rendering and accounting share effective status/gap codes, including omitted whole facts. The evaluation entry point is `node scripts/evaluate-memory-search.mjs --context --live --agent claude --repeats 2 --json`; ordinary `--context` runs explicitly labeled fallback only. Live evidence and recommendations remain pending; syntax and protocol fixtures do not satisfy acceptance.

The integrated implementation passed its fresh remote gate with all 1,070 assertions at `ca0dbfb2681b333bee7ce4faef8abe31be5116b7`; [helper-evidence.md](helper-evidence.md) retains the recorded protocol accounting and exact Claude weekly-quota blocker. On 2026-10-04, after review, the user explicitly approved publishing the current experimental build. Deliver that implementation now and defer the authenticated twenty-executions-per-mode live comparison to a follow-up. This delivery choice does not satisfy live acceptance or enable selective guidance; the existing acceptance bar and budgets remain unchanged. Adaptive thread-following was explanatory advice and is outside this release.

### Keep access and ownership in their owning change

The owner of `simple-machine-memory` confirmed the split through Paseo. Its private-owner/credential work and this selector/brief work can publish in either order. This change must call the shared selection and access helpers in whichever published version exists; it must not hard-code email or machine IDs as a new authorization rule. Tests cover the currently published role model and are reconciled against any intervening ownership release. No dependency on the cancelled installation-owned-memory-devices work is introduced.

## Risks / Trade-offs

- Keyword misses still remain → the brief states its selection limits and the diagnostic report measures misses; this release makes no semantic-search claim.
- Grouping could hide search relevance → admit entries under the byte budget in retrieval order, then group only the admitted facts.
- Repeated lookups or verbose tool output can waste context → choose ordinary text search for routine recall, a brief when source metadata helps, and JSON for programs; do not load both formats for the same unchanged query. The smaller default is a conservative context budget, not a measured relevance optimum.
- A cited source can return up to the existing 200,000-character stripped transcript cap → follow a source on demand to check a fact, never automatically fetch every citation. This change leaves source retrieval unchanged.
- The existing `--state` selector reads all matching rows before applying checkout-derived state and the final limit. This inherited path can cost more on a large store; ordinary brief requests retain the bounded search path. No production latency claim is made by request-count tests.
- A valid citation may point to an unavailable/private transcript → identify the fact and session without exposing raw bytes; source reads keep their current denial/no-R2 behavior.
- A shared-file refactor could alter search behavior → preserve all existing assertions and compare JSON/text IDs, filters, and ordering in the existing fixtures.
- Private facts could leak through a new output shape → use the enforced read path, test both formats and the brief with roles, and prohibit transcript retrieval during rendering.

## Migration Plan

No migration or provisioning is needed. Ship the CLI additions and docs as a minor payload release after the extension is implemented and reviewed. Keep helper selection experimental unless its live acceptance bar passes. The memory skill folder is already included as a whole; confirm the payload manifest behavior rather than adding a new per-file registry. Leave `VERSION` to `/ship`. Reverting helper invocation/guidance leaves the deterministic interfaces and all stored facts intact; removing all new read interfaces also changes no stored facts, sessions, credentials, or transcripts.

## Validation

Implementation coverage belongs in the existing memory store/Worker tests plus focused evaluation/brief tests where needed. Verify exact source IDs and bodies, stable grouping, UTF-8 caps, no replaced facts, no broadening by `--everyone`, reader-private facts, missing/denied transcripts, no-R2 operation, offline reporting, and JSON/text parity. The evaluation runner must classify a real synonym miss, reject a seeded forbidden result, and fail clearly on a CLI error.

Use `/save` for the remote script suite, coverage, and payload checks, including link/config/context checks; do not loosen checks. No main-app screen changes are planned, so there is no app preview. At implementation completion, demonstrate the brief with synthetic permitted facts and retain the evaluation report alongside the change. Planning runs only artifact validation and review-page generation. Review page: [review.html](review.html).

The helper extension adds meaningful remote tests for cumulative/concurrent reservations, multibyte text, oversized question or candidate inputs, duplicate IDs, untrusted fact instructions, forged model IDs, filter escalation, newly superseded facts, permission revocation, absent model/unsupported adapter, invalid JSON, process cancellation, missing/expired handles, exhausted output, and fallback without stale/private evidence. Its fresh remote gate and installed-host isolation evidence are retained separately from the earlier deterministic checks. Live synthetic retrieval remains quota-blocked and deferred under the user's explicit experimental-delivery choice; neither those earlier checks nor the recorded protocol evidence establishes live acceptance.
