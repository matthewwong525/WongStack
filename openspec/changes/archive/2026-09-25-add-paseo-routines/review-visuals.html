Who / job: a repo owner who wants a verb to run on a cadence. Done: Paseo holds a correct schedule and shows its next run.

  1. Any prompt or verb can follow the colon. The skill does not change it.
  2. Parsing the time needs judgment, so the agent does it. The dry run shows the result before anything is created. The primary worktree is used even when you call /routine from a feature worktree.
  3. This is the only path that sets isolation and mode together in one call. Checking the cron needs no judgment, so the script does it.
  4. Fail safe: without Paseo, /routine says so and changes nothing.
  5. The client is a private module of the Paseo CLI. A Paseo update can break it. The script stops and does not fall back to local isolation.
  6. The next run comes from the daemon, not from the agent, so it is the time Paseo will really use.
  7. The daemon runs one schedule at a time. A routine that is still running does not start again.
  8. This is the defect the change removes: a command-line schedule runs on top of your own work.
  9. These are the same defaults as the hand-made ClaymooApp /improve schedule.
  10. Runs often stop at a pending question. A kept agent is easier to find and answer than an archived one.
