What happens to a secret that a branch edits, from new worktree to merge, today and after this change.

After

New worktree: seed New

paseo.json setup runs worktree-secrets.mjs seed. It copies each primary live file into the worktree and records a baseline.

Details

Files: .env, app/.dev.vars, and app/.dev.vars.staging if present. Baseline: key names and value hashes, in the worktree's private Git folder. 2

↓

The branch edits a secret Changed

Where the edit goes depends on its kind.

↓ Choose one path

Add a key

Write it to the worktree copy and to the primary, now.

Details

Other worktrees and the primary can use the key at once.

Rotate a value

The old value is dead. Write the new one to both, now.

Details

The primary must not keep a dead value until the merge.

Delete a key or set a branch-only value

Write it to the worktree copy only.

Details

The primary changes only when the branch merges.

↓ All paths rejoin here

The branch merges

/ship merges the pull request.

↓

Promote to the primary New

/ship runs worktree-secrets.mjs promote. It applies the branch's deletions and changes to the primary. 1

Details

It compares three ways: the baseline, the worktree copy, and the primary. If the primary also changed a key after the seed, promote skips that key and names it. The output shows key names only, never values. A failure is a one-line skip and cannot fail the merged ship.

or, if the branch does not merge

Abandoned branch

The worktree is deleted. The primary never changes, except for adds and rotations already written there.

Today

New worktree

paseo.json copies only .env, one time, when it creates the worktree.

Details

app/.dev.vars is not copied.

↓

The branch edits a secret

The edit stays in the worktree copy.

Details

Worktree edits never reach the primary.

↓

The branch merges

No secrets step runs at merge.

Who / job: an agent or a person who edits a secret in a linked worktree.

  1. Promote compares against the baseline, not only the two files. A two-file compare would treat a key that another branch added to the primary as a deletion.
  2. No step prints a value. The baseline stores only hashes, and only in the worktree's private Git folder.
