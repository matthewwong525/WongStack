Four failure paths: what happens after this change, and today.

After

1. /ship merges a PR

Merge the pushed head Changed 1

gh pr merge --match-head-commit

Details

Actor: /ship. Action: merge only the commit it pushed. Result: a new commit on the PR makes the merge fail.

↓

Confirm the state is MERGED New

If not, stop. The branch and the PR stay.

Details

Actor: /ship. Action: read the PR state. Result: any state other than MERGED stops the run before cleanup.

↓ Only after MERGED

Retarget, then delete the branch Changed

Stacked PRs move to the default branch first.

Details

Actor: /ship. Action: retarget stacked PRs, then delete the remote branch. Result: no open PR loses its base.

2. The CI gate reads checks

Push, then wait for the head Changed 2

Poll until the PR head equals local HEAD.

Details

Actor: wait-for-checks.sh. Action: compare the PR head with HEAD. Result: it reads checks for the pushed commit only.

↓ No checks yet?

No workflow files Changed

NONE. PR review is the gate.

Details

Actor: the gate. Action: find no file under .github/workflows/. Result: NONE at once.

Workflow files New

Wait up to 60 s. Still none: UNKNOWN.

Details

Actor: the gate. Action: wait the grace period for a check to appear. Result: a check appears, or UNKNOWN stops the merge.

gh fails New

UNKNOWN. The merge stops.

Details

Actor: /ship preflight. Action: get an error or an empty answer from gh. Result: UNKNOWN, never NONE.

3. A staging deploy

Parse the config as JSONC Changed 3

Read env.staging.name. Ignore comments.

Details

Actor: cf-deploy.sh through node. Action: parse wrangler.jsonc with one parser. Result: database_name is never read as the Worker name. TOML config gets a clear refusal.

↓

Guard refuses a production name Changed

Staging never deploys to production.

Details

Actor: the production-name guard. Action: compare the staging name with production's. Result: a match stops the deploy.

4. Background memory capture

Pipe decisions on stdin Changed 4

Send them to memory.mjs. Write no file under .git/.

Details

Actor: the background capture run. Action: pipe the decision JSON to memory.mjs. Result: no write that dontAsk mode denies.

↓

Facts are written Changed

The run completes.

Details

Actor: memory.mjs. Action: record the facts in the store. Result: the next session digest shows them.

Today

1. /ship merges a PR

gh pr merge fails

The failure is not checked.

Details

Actor: /ship. Action: merge without a head check. Result: the run continues to cleanup.

↓

Branch deleted, PR closed

The work is not merged.

Details

Actor: /ship. Action: delete the remote branch. Result: GitHub closes the PR.

2. The CI gate reads checks

Push

GitHub has not registered the checks yet.

Details

Actor: /save. Action: push and read checks at once. Result: the list is empty.

↓

NONE, then merge

No check ran.

Details

Actor: the gate. Action: read an empty list, or a failed gh call, as NONE. Result: /ship merges without CI.

3. A staging deploy

A regex reads "name"

It matches database_name.

Details

Actor: the pack scripts. Action: match keys with a regex. Result: the wrong value is the Worker name. A "staging": in a comment is also read.

↓

Guard passes, deploy hits production

No error shows.

Details

Actor: cf-deploy.sh. Action: compare the wrong name. Result: the staging deploy can reach production.

4. Background memory capture

Write decision JSON under .git/

dontAsk mode denies the write.

Details

Actor: the background capture run. Action: write a file under .git/. Result: permission denied.

↓

The run fails

No facts are written.

Details

Actor: the capture run. Action: stop on the denied write. Result: this happens on every run.

  1. Cleanup is last. A failed merge leaves the branch and the PR as they were.
  2. NONE means "this repo has no CI", not "no check yet". The 60 s grace period and a failed gh call give UNKNOWN, which stops the merge.
  3. One JSONC parser reads the config for all pack scripts. The guard compares the real Worker name.
  4. Capture uses stdin, so it needs no file write that the background permission mode denies.
