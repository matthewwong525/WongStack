Bare /ship on a clean branch, or on the default branch with nothing to ship. Warm = this conversation establishes the work. Cold = it establishes nothing, and only a stale openspec list entry is left.

  1. The stop the change removes. The work is agreed, the branch is clean, and the only thing missing is the argument the user typed a minute ago.
  2. /ship asks one question and asks it as /apply's written resolve order. Items 1–3 chain — a change the user named, the change created or discussed in this conversation, or an active change whose name matches the current branch — item 3 is what covers a planned-but-unimplemented change sitting on its own branch. So does the separate branch where no change exists yet and the session states clear implementation intent. Item 4, the fenced sole-active-change fallback, and "unclear" stop. The resolver stays in one place: /ship writes no rule of its own about what counts as intent.
  3. Both checkpoints of a one-go run stand: /apply's completion save here, then the archive save in Step 3. Nothing collapses them.
  4. Item 4 is the sole-active-change fallback. It is the branch that would build and merge a stale scaffold nobody asked for, so it is the one that keeps the stop.
  5. The stop is spoken, not silent — the user learns to type an intent instead of wondering why nothing happened.

  4. Composes with never merge as a way of stopping — an /apply that ends with tasks still pending stops /ship before the archive, which the runbook already specifies.
