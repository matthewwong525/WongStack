Change 2 · flow

#/ means no change chosen

The sheet stays shut: the link named a target, so the target opens. Step back to the change list whenever the reviewer wants the rest.

Who / job: a reviewer on a phone, opening a review link to judge what a change proposes. Done: they have seen every change and left their notes. Context: a phone, away from the desk, usually a link from chat; the list and the stage cannot share the screen. Common case: a link with no fragment — read the whole list. Edge case: a deep link to one visual. Frequency: assumed a few reviews a day per reviewer, most of them on a desktop; the phone read is the one that fails today. Primary action: choose a change — the sheet's rows are the target, so the chrome keeps no filled button of its own.

  1. Phone is the (max-width: 760px) media query, not the chrome's View toggle. The toggle redraws a screen visual at phone width while the page layout stays desktop, so a desktop reviewer who toggles View must not lose the panel they are reading. The media query is the same one the sheet's own CSS keys off, so the router and the layout can never disagree.
  2. No bullet is current, so the counter falls to the kit's existing <n> changes branch and Previous to its existing disabled branch. Nothing new is drawn — a state the kit already had becomes reachable on a phone.
  3. Next from the empty selection opens change 1. A reviewer who wants the first change taps twice, and the second tap is always in the same place.
  4. The landing stays behind the sheet, muted, with no change pre-selected. A change 1 opened behind the sheet is the same problem one layer down: a change the reviewer never chose.
  5. State direct: a fragment that names a visual, a state, or a mark opens that target with the sheet shut. Opening the sheet on every phone load would bury the target of a link someone sent you.
