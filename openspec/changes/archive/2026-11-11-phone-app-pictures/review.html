Why

A plan that changes a screen shows real pictures of the app, made from a throwaway copy that runs on the preview or on this computer. That only works for a web app. For a phone app or a desktop app, every step fails, so the plan falls back to a gray sketch, and it skips the picture of today's screen too, though that screen exists. In Relay Everything on 2026-11-11, a screen test drew the real phone app on this computer in about 2 seconds a picture, with no phone. Every repo with such an app should do the same.

What Changes

  1. 1
    A phone or desktop app gets real pictures in its plan. The plan draws the app with the app's own screen test, in the throwaway copy, with sample data: Before from the copy as it is today, After from the same copy with the plan's edits. Pictures from Relay Everything's phone app, drawn this way: Before this, the same plan showed only a sketch:
  2. 2
    Each repo writes down its own way once. The first plan that needs pictures of such an app finds how to draw them, then writes the steps on the repo's own page for that app, so the next plan only follows them. Until then, the plan works it out and does not give up at the first failed step.
  3. 3
    A sketch stays only for what no test can draw, such as the phone's own menus, keyboard, share sheet, or permission questions. The plan still shows the real Before, and one line names the part only the phone draws. The page's warning about a sketch now names the screen test too.

What the build needs

  1. Nothing.

  2. Non-goals: no new command that runs a repo's screen test; no change to how web apps get their pictures; no device or simulator runs while planning.

Decisions

  1. asked2026-11-11

    Asked whether a phone or desktop app gets a new picture command or only written steps → chose written steps only, because the screen test is different for every plan, so a command would save only one run and a copy.

  2. assumed2026-11-11

    Assumed: a repo names its screen-test route on its own wiki page for that app, linked from a path rule for the app's folder, as Relay Everything does with wiki/development/phone-pictures.md and .agents/rules/mobile.md, because a WongStack page can't know each repo's test kit.

  3. assumed2026-11-11

    Assumed: the first plan that needs the route writes that page, because it is repeatable knowledge by the wiki rules.

  4. assumed2026-11-11

    Assumed: the prototype's steps move to a new page wiki/prototypes.md, and review-pages.md keeps a short ## The prototype section, because that page is at 2960 of its 3000 words and other repos link that heading.

  5. assumed2026-11-11

    Assumed: prototype.mjs start stays as it is, because it already makes a plain git copy for any app; only upload and serve are web-only.

  6. assumed2026-11-11

    Assumed: the example pictures come from Relay Everything's plan "Paste in a note feels like the iPhone's own", because they are real screen-test output with sample data and no private data.

  7. assumed2026-11-11

    Assumed: a screen test uses the app's own screen size and width (an iPhone's, or a desktop window's), not always a phone's, because the route covers desktop apps too; the second look found it.

  8. assumed2026-11-11

    Assumed: the copy loses the pictures a screen test saved, as well as the test, before finish, because finish keeps every new file in the diff the build reads.
