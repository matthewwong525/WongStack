# Three review buttons, with notes carried into the build

**Status:** ready-to-ship
**Branch:** review-notes-build
**Open questions:** none

## Why

The review page hides building behind a menu and makes you send notes, wait for the plan to change, then ask to build. You should be able to leave notes and choose what happens next in one step.

## What Changes

- **Three buttons stay visible at the bottom.** Send notes, Build it, and Build and publish are directly available on a connected review page, including on a small phone.
  ```text
  BEFORE
  Plan and your notes
  [Send notes] [···]
                └─ Build / Build and publish

  AFTER — phone
  Plan and your notes
  ┌──────────┬──────────┬──────────────┐
  │Send notes│ Build it │ Build and    │
  │          │          │ publish      │
  └──────────┴──────────┴──────────────┘
  Publishing: confirm above the buttons.
  Waiting: buttons pause, status shows.
  Closed: Copy notes stays available.
  ```
- **Build with your saved notes in one step.** Either build choice sends the notes with your choice. The assistant updates the plan and immediately builds; Build and publish also publishes after its checks. Send notes alone still updates the plan and waits.
  ```text
  BEFORE
  Save notes → Send → wait → Build

  AFTER
  Save notes → Build with notes
               ├─ update plan
               └─ build → preview
  Save notes → Build and publish
               └─ update → build → publish
  ```
- **Notes stay safe when a request fails.** Only an acknowledged request marks its included notes as sent. A changed plan asks you to reload; a closed link leaves your notes available to copy.
- **Desktop text is easier to read, with shorter buttons aligned to the plan.** The plan uses larger text on a computer, and the three bottom buttons expand to the same padded content edges.
  ```text
  DESKTOP BEFORE
  Small plan text
  [     Send notes     ][     Build     ]
  [            Build and publish       ]

  DESKTOP AFTER
  + Larger plan text
  [ Send notes ][ Build it ][ Publish ]
  + Button edges align with plan edges
  ```

**Non-goals:** Changing the notes editor, changing link expiry, or publishing without the chosen publish action.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `ux-wireframes`: Visible build buttons and saved notes included in a build request, with current progress and failure behavior.
- `asking-the-user`: Review notes accompanied by an explicit build choice update the plan and continue to that authorized action.
- `reply-links`: Registered actions may include bounded reviewer notes in the same message without changing their fixed instruction or chat target.

## Impact

Review kit, review builder action messages, reply-link action endpoint, planning/building skill routing, browser and endpoint tests, owning wiki pages, and a minor payload release. No dependency or app data changes.

# Design

## Context

See proposal.md for the problem. The offline review kit also runs on authenticated reply links. `act` currently accepts a registered action and current file version; `send` accepts notes under a fixed stop-before-build header. The kit blocks building when unsent notes exist and hides build choices in a three-dot popover.

## Goals / Non-Goals

Use the existing kit and endpoint, without a new service or dependency. Preserve offline copying, version checks, request locking, rate/size limits, publish confirmation, and note/draft storage.

## Decisions

- Put Send notes, Build it, and Build and publish directly in the footer. Use a responsive three-column layout and allow labels to wrap on small phones. Keep one primary action, Send notes, with the build choices outlined. Note counts remain visible in the header. The publish confirmation stays above the footer and is dismissible with Escape or an outside tap, returning focus appropriately.
- Desktop widths above 700px use 20px reading text and larger supporting labels, with 18px footer labels in 44px-tall buttons. The three equal-width buttons span the document's inner content width, using the same 700px maximum and 12px padding. Confirmation and status align to that same right edge.
- Extend the action request with optional `text` containing saved unsent note bullets. Validate its type and limit before consuming the action; append it beneath the registered fixed instruction. Empty or omitted text keeps today's action-only behavior. An invalid non-string or oversized text must never wake the chat. The client cannot replace the action message, header, or chat target.
- Snapshot notes at the moment of sending. Send exactly one action request rather than sending notes first: a separate note send could cause a rebuild and invalidate the action's version. Mark only acknowledged snapshot notes as sent, leaving drafts and later edits unsent. On rate limiting, a changed version, an unconfirmed send or a closed link, retain the notes for retry/copy and do not claim success.
- The builder's registered build and publish messages explicitly tell the assistant to apply attached review notes before `/apply` or `/ship`, without stopping for another build choice. Update `/plan`'s review-note handling to return to an already authorized caller; update `/apply` to process attached notes before readiness selection. Question notes receive an answer, without invented plan edits; a missing plan or real blocker still stops. Standalone Send notes keeps the existing header and plan-only reach.
- Keep historical review pages unchanged. Regenerate this active page after the kit changes. Add a minor Next changelog entry; VERSION is left for delivery.

## UX

### Use-case brief

The owner reviews a plan on a phone or laptop, leaves notes, and chooses whether to update it, build a preview, or publish. Done means the assistant receives both the requested action and the saved changes in one step. Assume this happens once per reviewed change. The common case is saved notes followed by a build; old tabs, closed links and draft-only text are edge cases. Mirror the current review page, keeping its notes editor and document intact.

### Flow

Save notes, then tap one of the three footer buttons. Build it sends notes with build authorization. Build and publish opens the current confirmation; confirming sends notes with publish authorization. Send notes updates only the plan. A waiting request disables other reply actions immediately. Failure leaves notes available; changed content asks for reload.

### Hierarchy

Send notes retains the single filled button. Both build choices are outlined and directly visible. Confirmation has one filled Yes, publish button and Cancel. Progress and results remain above the footer without changing its height.

### Review

[review.html](review.html), What Changes item 1, sketches the footer before and after and its confirmation/waiting/closed states. Item 2 compares the note-to-build flow. Item 4 sketches the larger desktop text and buttons aligned with the content.

### Components

Use the kit's existing footer, note button, ready controls, spinner, confirmation group and status region. Remove the menu toggle and build-choice popover; retain a panel only for publish confirmation.

## Risks / Trade-offs

- Three full labels need more height on 320px phones → let labels wrap within equal-width columns, preserve 44px targets, test no overflow and footer stability during progress.
- Notes changing while the request is pending → mark only the exact submitted note content, keep any newer edit unsent.
- Stale tabs or unconfirmed delivery → preserve version checks, bounded request locks and acknowledgement; never mark notes sent on failure.
- Skill text has a strict context budget → trim replaced instructions and run the context check; do not loosen its limits.

## Migration Plan

Rebuild active review pages with the updated kit and action registration. Archived pages and saved note storage stay intact. No manual credential or data migration.

## ADDED Requirements

### Requirement: A review build choice carries its notes into the build

When review notes accompany an explicit Build it or Build and publish choice, the assistant SHALL apply requested plan changes and answer question notes, then continue directly into the authorized build or publish action without asking for a further build choice. Question notes SHALL NOT cause unrequested plan edits. A missing plan or material blocker SHALL stop the action and be reported. Notes sent alone SHALL retain their plan-only reach.

#### Scenario: Notes with build authorization

- **WHEN** the reviewer sends a rename note with Build it
- **THEN** the plan is updated and the assistant builds it without waiting for another build instruction

#### Scenario: Notes alone

- **WHEN** the reviewer sends the same note through Send notes
- **THEN** the plan is updated and building waits for a separate build choice

## MODIFIED Requirements

### Requirement: A page can offer fixed actions

A reply link's opener MAY name actions, each with the message it sends. A page on that link SHALL be able to trigger an action by name only, with the link's secret, and the chat that opened the link SHALL receive that action's fixed message exactly as the opener wrote it, followed by any optional bounded reviewer text supplied with the action. The page SHALL never replace that fixed instruction or chat target; invalid or oversized text SHALL be refused before the action is delivered. An action SHALL be refused when the page's file has changed since the page read it, and SHALL be accepted at most once per version of the file. The page SHALL be told which actions the link offers and whether a trigger reached the chat.

#### Scenario: The person taps an action

- **WHEN** the person triggers a named action on an open reply link whose file is unchanged
- **THEN** the chat receives that action's fixed message once, and a second trigger sends nothing

#### Scenario: The file changed since the page loaded

- **WHEN** the page's file is rebuilt and the person triggers an action from a tab opened before
- **THEN** nothing reaches the chat and the page is told the file changed

#### Scenario: An action carries reviewer notes

- **WHEN** the person triggers an action with valid saved notes on an unchanged page
- **THEN** the chat receives the fixed action instruction and those notes together in one message, and the page receives acknowledgement only after confirmed delivery

<!-- file specs/ux-wireframes/spec.md utf8 2501 -->
## MODIFIED Requirements

### Requirement: A plan on a reply link can start its build

On an open reply link, the review page SHALL offer Send notes, Build it, and Build and publish as three directly visible bottom buttons, reachable without scrolling on a phone. A build choice SHALL send the selected action with every saved unsent note in one request, so the chat applies the notes and continues into the selected build or publish action without another build choice. Build and publish SHALL ask once more on the page before sending. The page SHALL mark only acknowledged submitted notes as sent and SHALL preserve unsent notes on failure. A changed plan SHALL prevent the action and ask for reload. Opened from disk or after the link closes, the page SHALL show no build choices and SHALL retain note copying. Send notes alone SHALL build nothing.


#### Scenario: Build it from the page

- **WHEN** the reviewer taps *Build it* at the top of a long plan on a phone, on an open reply link with no unsent note
- **THEN** all three buttons are directly reachable without scrolling, the bottom bar has no sideways overflow, the chat starts building that change, and the page says the chat was asked

#### Scenario: An unsent note

- **WHEN** the reviewer taps *Build and publish* with one saved note not yet sent and confirms publishing
- **THEN** the chat receives the chosen action and note together, updates the plan, and builds and publishes without a further build choice; the acknowledged note is marked sent

### Requirement: Pasted notes update the plan and stop

Pasted notes sent alone SHALL update that change's artifacts with no question round, only for notes that ask for a change, and log what each such note changed or why it was declined; a note that asks a question SHALL be answered as `asking-the-user` requires, with no edit. The reply SHALL rebuild the page when anything changed and end with the plan's link and whether to build now. Notes alone SHALL build nothing; an explicit accompanying build choice SHALL authorize applying those notes and continuing directly to that action, and SHALL change nothing when the change is not in this checkout.

#### Scenario: Notes pasted

- **WHEN** a reviewer pastes notes asking for changes to a change
- **THEN** the proposal, design, specs, and tasks reflect them, and no task is implemented

#### Scenario: The change is not here

- **WHEN** the change is not in the current checkout
- **THEN** the reply says so, and nothing changes

    const w = d.art.offsetWidth, fw = d.frame.clientWidth - 1;
    if (w > 0 && fw > 0) size(d.art, BASE * Math.min(1.25, fw / w), fw);
  }
  function reveal(el) {
    const fig = el.closest('details');
    if (fig && !fig.open) { fig.open = true; drawings.forEach(fit); }
  }
  function scale(f, cx, cy) {
    f = Math.max(V.lo, Math.min(V.hi, f));
    const k = f / V.f, x = (vframe.scrollLeft + cx) * k - cx, y = (vframe.scrollTop + cy) * k - cy;
    V.f = f; view.art.style.fontSize = f + 'px';
    vframe.scrollLeft = x; vframe.scrollTop = y;
    const atFit = f <= V.lo * 1.001;
    vbar.firstChild.textContent = (atFit ? 'Fit · ' : '') + Math.round(f / BASE * 100) + '%';
    vb[0].disabled = atFit; vb[2].disabled = f >= V.hi * 0.999;
  }
  function openViewer(d) {
    hideChip();
    view = d; viewer.hidden = false; document.body.classList.add('viewing');
    vframe.appendChild(d.art);
    d.art.style.fontSize = BASE + 'px';
    const fw = vframe.clientWidth - 1;
    V.lo = size(d.art, BASE * fw / Math.max(1, d.art.offsetWidth), fw);
    V.hi = Math.max(V.lo * 4, 40); V.f = V.lo;
    vframe.scrollLeft = vframe.scrollTop = 0;
    scale(V.lo, 0, 0);
    vb[3].focus({ preventScroll: true });
  }
  function closeViewer(restore) {
    if (!view) return;
    const d = view;
    view = null;
    d.frame.insertBefore(d.art, d.frame.firstChild);
    viewer.hidden = true; document.body.classList.remove('viewing');
    fit(d); bar();
    if (restore) d.enlarge.focus({ preventScroll: true });
  }
  vbar.addEventListener('click', function (e) {
    const i = Array.prototype.indexOf.call(vb, e.target);
    if (i === 3) closeViewer(true);
    else if (i >= 0) scale([V.f / 1.25, V.lo, V.f * 1.25][i], vframe.clientWidth / 2, vframe.clientHeight / 2);
  });
  vframe.addEventListener('wheel', function (e) {
    if (!e.ctrlKey && !e.metaKey) return;
    e.preventDefault();
    const r = vframe.getBoundingClientRect();
    scale(V.f * (e.deltaY < 0 ? 1.1 : 1 / 1.1), e.clientX - r.left, e.clientY - r.top);
  }, { passive: false });
  // One finger scrolls natively; two fingers pinch around their midpoint.
  let pinch = null;
  const span = function (t) { return Math.hypot(t[0].clientX - t[1].clientX, t[0].clientY - t[1].clientY) || 1; };
  vframe.addEventListener('touchstart', function (e) { if (e.touches.length === 2) pinch = { f: V.f, dist: span(e.touches) }; }, { passive: true });
  vframe.addEventListener('touchmove', function (e) {
    if (!pinch || e.touches.length !== 2) return;
    if (e.cancelable) e.preventDefault();
    const r = vframe.getBoundingClientRect(), t = e.touches;
    scale(pinch.f * span(t) / pinch.dist, (t[0].clientX + t[1].clientX) / 2 - r.left, (t[0].clientY + t[1].clientY) / 2 - r.top);
  }, { passive: false });
  vframe.addEventListener('touchend', function (e) { if (e.touches.length < 2) pinch = null; });
  document.addEventListener('gesturestart', function (e) { if (view) e.preventDefault(); });
  all('.drawing', function (fig) {
    const frame = fig.querySelector('.frame'), enlarge = document.createElement('button');
    enlarge.type = 'button'; enlarge.className = 'enlarge'; enlarge.textContent = 'Full screen';
    frame.appendChild(enlarge);
    const d = { fig: fig, frame: frame, art: fig.querySelector('.art'), count: fig.querySelector('.count'), enlarge: enlarge };
    drawings.push(d);
    fig.addEventListener('toggle', function () { fit(d); });
    frame.addEventListener('click', function (e) { if (!e.target.closest('[data-open]')) openViewer(d); });
  });

  // ── direct links: #/why, #/<n>, #/decisions/<n> ──
  function jump() {
    const m = /^#\/(?:decisions\/(\d+)|(\d+)|(why|changes|decisions))$/.exec(location.hash);
    const el = m ? $(m[1] ? 'decision-' + m[1] : m[2] ? 'item-' + m[2] : m[3]) : null;
    if (!el) return;
    all('.hit', function (n) { n.classList.remove('hit'); });
    el.classList.add('hit');
    el.scrollIntoView({ block: 'start' });
  }

  // ── copy: saved notes only, as notes on the plan: each asks or changes something ──
  // A note sent through a reply link is in the chat already, so it is never copied or sent again.
  function unsent() { return data.notes.filter(function (n) { return !n.sent; }); }
  function snapshot() { return unsent().map(function (n) { return { id: n.id, label: n.label, text: n.text }; }); }
  function acknowledge(notes) {
    notes.forEach(function (submitted) {
      data.notes.forEach(function (current) {
        if (current.id === submitted.id && current.label === submitted.label && current.text === submitted.text) current.sent = true;
      });
    });
    persist();
  }
  function bullets(notes) {
    return notes.map(function (n) {
      const w = where(n.id);
      return '- ' + w.spot + ' (' + n.label.slice(w.kind.length + 1) + '): ' + n.text.replace(/\s*\n\s*/g, ' ');
    });
  }
  function notesText() {
    return ['Notes on the plan ' + CHANGE + ' from the review page. Don\'t build yet.'].concat(bullets(unsent())).join('\n');
  }
  function toast(text) {
    $('toast').textContent = text; $('toast').classList.add('show');
    setTimeout(function () { $('toast').classList.remove('show'); }, 2000);
  }
  function plural(n) { return n + (n === 1 ? ' note' : ' notes'); }
  // One routine for Copy notes and Save: the Clipboard API, else select #copybuf and execCommand, then hand focus back.
  function copyNotes(done, failed) {
    const buf = $('copybuf');
    buf.value = notesText();
    const fallback = function () {
      const back = document.activeElement;
      buf.select();
      const ok = document.execCommand('copy');
      if (back && back !== buf && back.focus) back.focus({ preventScroll: true });
      if (ok) done(); else failed();
    };
    if (navigator.clipboard && navigator.clipboard.writeText) navigator.clipboard.writeText(buf.value).then(done, fallback); else fallback();
  }
  // Nothing to copy or send: say why. True when it spoke.
  function nothing(verb) {
    if (unsent().length) return false;
    toast(data.notes.length ? 'Every note is already sent.' : 'No saved notes yet. Drafts are not ' + verb + '.');
    return true;
  }

  // ── reply link: at a web address with #key=, the bar's button sends unsent notes to the chat that made the plan ──
  // `live` is the link's key while the link is open. The key stays in memory and this tab's session, never in a link.
  let live = null, connecting = false, pending = null;
  function setLive(key) {
    live = key;
    if (!key) hideActions();
    all('.copies', function (el) { el.textContent = key ? 'Send notes sends your saved notes to the chat.' : 'Saving a note copies all your notes.'; });
    bar();
  }
  // One request owns every reply control until the response body has been read.
  function busy(kind) {
    pending = kind;
    bar();
  }
  function linkKey() {
    if (!/^https?:$/.test(location.protocol) || !window.fetch) return null;
    const m = /(?:^#|&)key=([0-9a-f]{64})(?:&|$)/.exec(location.hash), at = 'wong-reply-key:' + location.pathname;
    try {
      if (m) window.sessionStorage.setItem(at, m[1]);
      return m ? m[1] : window.sessionStorage.getItem(at);
    } catch (e) { return m ? m[1] : null; }
  }
  function ask(path, key, body) {
    const headers = { 'x-reply-key': key };
    if (body) headers['content-type'] = 'application/json';
    return fetch(path, { method: body ? 'POST' : 'GET', cache: 'no-store', headers: headers, body: body ? JSON.stringify(body) : undefined });
  }
  async function sendNotes() {
    const notes = snapshot(), n = notes.length;
    if (pending || connecting || nothing('sent')) return;
    busy('send'); says('Sending your notes…');
    // A closed link or an unreachable chat: the same tap copies, and the page goes back to Copy notes.
    const closed = function () {
      setLive(null); says('This link has closed. Copy your notes into chat.');
      copyNotes(function () { toast('This link has closed. Copied ' + plural(n) + ': paste them into chat.'); },
        function () { toast('This link has closed. Tap Copy notes to copy them.'); });
    };
    try {
      const r = await ask('send', live, { text: bullets(notes).join('\n') });
      if (r.status === 429) { says('Wait a few seconds, then tap Send notes again.'); toast('Wait a few seconds, then tap Send notes again.'); return; }
      if (!r.ok) { closed(); return; }
      const answer = await r.json();
      if (!answer || answer.sent !== true) { closed(); return; }
      acknowledge(notes);
      says('Sent ' + plural(n) + ' to the chat.');
      toast('Sent ' + plural(n) + ' to the chat.');
    } catch (e) { closed(); }
    finally { busy(null); }
  }
  $('copy').addEventListener('click', function () {
    if (pending || connecting) return;
    if (live) { sendNotes(); return; }
    const n = unsent().length;
    if (nothing('copied')) return;
    copyNotes(function () { toast('Copied ' + plural(n) + '. Paste them into chat.'); },
      function () { toast('Copy failed. Copy the notes list by hand.'); });
  });

  // ── visible build choices, with publish confirmation above the footer ──
  let version = null;
  const publishButton = $('ready').querySelector('[data-ready="publish"]');
  function says(text) { $('ready-message').textContent = text; $('ready-says').hidden = !text; }
  function closeActions(focus) {
    const wasOpen = !$('ready-confirm').hidden;
    $('ready-confirm').hidden = true;
    publishButton.setAttribute('aria-expanded', 'false');
    if (focus && wasOpen && !$('ready').hidden) publishButton.focus({ preventScroll: true });
    bar();
  }
  function hideActions() {
    const focused = $('ready').contains(document.activeElement);
    closeActions(false);
    $('ready').hidden = true;
    if (focused) $('copy').focus({ preventScroll: true });
    bar();
  }
  document.addEventListener('keydown', function (e) {
    if (e.key === 'Escape' && !$('ready-confirm').hidden) { e.preventDefault(); closeActions(true); }
  });
  document.addEventListener('pointerdown', function (e) {
    if (!$('ready').contains(e.target)) closeActions(false);
  });
  $('ready').addEventListener('focusout', function (e) {
    if (e.relatedTarget && !$('ready').contains(e.relatedTarget)) closeActions(false);
  });
  // Only the row contributes to page padding; popovers and status never increase its height.
  function bar() {
    const el = $('copy').parentNode, waiting = connecting || !!pending;
    $('copy-label').textContent = connecting ? 'Connecting…' : pending === 'send' ? 'Sending…' : live ? 'Send notes' : 'Copy notes';
    $('copy').disabled = waiting;
    $('copy').querySelector('.spinner').hidden = !(connecting || pending === 'send');
    el.setAttribute('data-busy', String(waiting));
    $('copy').setAttribute('aria-busy', String(connecting || pending === 'send'));
    root.style.setProperty('--choices', $('ready-confirm').offsetHeight + 'px');
    $('ready-says').querySelector('.spinner').hidden = !waiting;
    all('[data-ready]', function (b) {
      const step = b.getAttribute('data-ready');
      b.disabled = waiting;
      b.setAttribute('aria-busy', String(pending === (step === 'yes' ? 'publish' : step) && step !== 'publish'));
      const spinner = b.querySelector('.spinner');
      if (spinner) {
        const active = pending === (step === 'yes' ? 'publish' : step);
        spinner.hidden = !active;
        b.querySelector('span:last-child').textContent = active ? 'Sending…' : step === 'yes' ? 'Yes, publish' : 'Build it';
      }
    });
    if (el.offsetHeight) root.style.setProperty('--bar', el.offsetHeight + 19 + 'px');
  }
  function offer(answer) {
    const names = answer && answer.actions;
    if (!Array.isArray(names) || names.indexOf('build') < 0 || names.indexOf('publish') < 0 || typeof answer.version !== 'string') return;
    version = answer.version;
    $('ready').hidden = false;
    bar();
  }
  async function act(name) {
    if (pending || connecting || !live) return;
    const notes = snapshot();
    busy(name); says('Sending your request…');
    const closed = function () { setLive(null); says('This link has closed. Copy your notes and choose in the chat.'); toast('This link has closed. Copy your notes and choose in the chat.'); };
    try {
      const body = { action: name, version: version };
      if (notes.length) body.text = bullets(notes).join('\n');
      const r = await ask('act', live, body);
      if (r.status === 429) { says('Wait a few seconds, then tap again.'); return; }
      const a = await r.json() || {};
      const line = r.status === 200 && a.sent === true ? 'Asked the chat to build' + (name === 'publish' ? ' and publish.' : '.')
        : r.status === 409 && a.changed === true ? 'The plan changed. Reload to read it first.'
        : r.status === 409 && a.done === true ? 'The chat was already asked.' : '';
      if (r.status === 410 || r.status === 403) { closed(); return; }
      if (!line) { says('The request was not confirmed. Your notes are saved. Try again.'); return; }
      if (r.status === 200 && a.sent === true) acknowledge(notes);
      hideActions(); says(line);
    } catch (e) { says('The request was not confirmed. Your notes are saved. Try again.'); }
    finally { busy(null); }
  }
  $('ready').addEventListener('click', function (e) {
    const button = e.target.closest('[data-ready]');
    if (!button || pending || connecting) return;
    const step = button.getAttribute('data-ready');
    if (step === 'build' || step === 'yes') act(step === 'yes' ? 'publish' : 'build');
    else if (step === 'cancel' || step === 'publish') {
      says('');
      $('ready-confirm').hidden = step === 'cancel';
      publishButton.setAttribute('aria-expanded', String(step === 'publish'));
      bar();
      $('ready').querySelector('[data-ready="' + (step === 'cancel' ? 'publish' : 'cancel') + '"]').focus({ preventScroll: true });
    }
  });

  let width = root.clientWidth;
  window.addEventListener('resize', function () {
    if (root.clientWidth !== width) {
      width = root.clientWidth; hideChip();
      if (view) { const d = view; closeViewer(false); openViewer(d); }
    }
    drawings.forEach(fit);
    if (open) place();
    bar();
  });
  window.addEventListener('hashchange', jump);
  render();
  jump();
  const key = linkKey();
  if (key) {
    connecting = true; says('Connecting to the chat…'); bar();
    (async function () {
      try {
        const r = await ask('alive', key);
        if (!r.ok) return;
        const answer = await r.json();
        if (!answer || typeof answer !== 'object') return;
        setLive(key); offer(answer);
      } catch (e) { /* not live: the page copies */ }
      finally { connecting = false; says(''); bar(); }
    }());
  }
}());
