Check result

The Test check passes or fails.

Details

Actor: GitHub. Action: report the job result. Result: every /save and /ship waits for it.

Who / job: a developer who pushes and waits for the Test check. Done: the check reports, and Stryker tests only changed mutants. Frequency: every push.

  1. The key holds a hash of the lockfile, Stryker config, and Vitest config. Stryker's incremental mode does not see a dependency or config change. A new hash gives a miss, so that run tests every mutant, and an old result cannot hide a surviving mutant.
  2. Save runs also when the test fails. The next push fixes the failure, and it then reuses every result that is still valid.
  3. Each save gets a new key that ends in the run ID. GitHub cannot overwrite a cache entry. Restore by prefix searches the current branch first, then the default branch, so no extra logic is necessary.
