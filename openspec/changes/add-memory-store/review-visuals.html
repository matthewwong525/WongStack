What memory does in a session: after this change, and today.

After

A session starts Kept

You open Claude or Codex in a checkout of the repo.

Details

Actor: you. Action: start a session. Result: the agent's SessionStart hook fires. Agents without a start hook follow an AGENTS.md instruction.

↓

The start hook runs a script with no model New

All network work fits in a 1.5 s budget.

Details

Actor: SessionStart hook. Action: append this checkout to the registry, count the pending sessions, check the local spool for facts, and check if consolidation is due. The hook does not upload spooled facts, because each fact must pass the write gate, and the gate needs a model. Result: the facts for the digest and one yes or no answer about background work.

↓

The hook prints the digest New 1

Code builds it from one SQL query of live facts. It stays frozen for the whole session.

Details

Actor: script. Action: read the facts that no later fact supersedes, ordered by type and then by recency, and add the open thread facts of the current branch's change. The digest stops at 150 lines or 25 KB. Each line shows the type, the body, the slug, the age in days, the author, and the fact id. Its header reports the result of the last background run. Result: the agent starts with the team's memory. When the store cannot be reached, the script prints the last digest from a local cache in the git common directory.

↓ Are sessions pending, are facts in the spool, or is consolidation due?

If no New

Nothing else runs.

Details

Actor: script. Action: exit. Result: the session starts with only the digest added.

If yes New 2

The hook starts a detached background run and returns at once.

Details

Actor: hook. Action: start the same agent's command-line tool (claude or codex) in headless mode with a small model. The main agent launches nothing. Result: your first reply is not delayed. If a headless run cannot start, the hook tells the main agent to start a background subagent instead.

↓ Only the "yes" path continues, in the background

The run captures past sessions New 3

At most 5 sessions idle for 1 hour or more, newest first, plus the spooled facts.

Details

Actor: background run. Action: code strips each transcript and replaces known .env values. A session with #private in any of your messages is skipped completely. When the store has an R2 bucket, code uploads the raw transcript to it, and the model proposes facts from the stripped text. The run never reads its own sessions or subagent transcripts. The run also takes the facts from the local spool. Result: proposed facts for each session, and the spooled facts, all ready for the write gate.

↓

The write gate decides each fact New 4

The model sees similar facts, then adds, supersedes, or drops.

Details

Actor: script and model. Action: the script shows the live facts on the same slug and the top keyword matches. The model chooses add, supersede <id>, or drop. Result: only new facts are written, and a replaced fact points to its successor.

↓ When 24 hours and 5 captured sessions have passed since the last consolidation

The same run consolidates New

It merges duplicates and supersedes contradicted facts, newest wins.

Details

Actor: background run. Action: merge duplicate facts, supersede contradicted facts with the newest one, and record the counts in a runs row. The counts include duplicates that the write gate missed. Result: the live set stays small. Nothing is deleted, and no command runs by hand.

↓ Writes to

The memory store <repo>-memory New

D1 keeps facts, sessions, tags, and runs. An optional private R2 bucket keeps raw transcripts.

Details

Actor: memory script. Action: call the Cloudflare REST API with the memory token. CI never receives this token. Result: rows in D1, and objects in R2 when the bucket exists. Without R2, no transcript is stored and everything else works. A private session gets only its session row, with no upload.

↓ During the work, the verbs read and write the same store

/explore Changed

Searches the store on the intent before it asks.

Details

Actor: /explore, and /plan through it. Action: keyword search with tags. Result: the questions start from what the team already knows. Each printed fact shows its age, author, and source.

/save Changed

Extracts facts through the write gate.

Details

Actor: /save. Action: propose facts from the session and pass each one through the write gate. Result: facts in the store. When the store cannot be reached, the facts wait in an ignored local spool. The next session start sees the spool and starts the background run, which passes the facts through the write gate and uploads them.

/continue Changed

Reads the slug's live facts and open threads.

Details

Actor: /continue. Action: query the facts for the slug. Result: a cold resume on any machine gets every saved and captured fact.

/ship Changed 5

Distills reusable facts into wiki pages, inside the ship PR.

Details

Actor: /ship. Action: read the change's facts and edit the owning wiki pages with reusable process facts. Result: a person reviews the edits in the ship pull request, before the change archives.

↓ Later

Only /continue reads the note file Changed

Nothing revisits a note. Search is grep.

Details

Actor: /continue. Action: read notes/<slug>.md. Result: the saved context, with no index. No step removes a stale or duplicate note.

  1. The digest stays frozen for the whole session, so prompt caching holds. Facts written during the session show in the next digest. Code builds the digest with no model, so a session start costs no tokens for memory.
  2. A detached run adds no cost to your first reply, because the main agent launches nothing. The run spends your own model quota without a visible turn. The next digest header reports what it did.
  3. One #private in any of your messages skips the whole session. The session row records the skip, so the session is not read again, and nothing from it is uploaded.
  4. The write gate uses the model to catch paraphrases, so embeddings are not necessary yet. Consolidation is the backstop. Its counts show when the gate misses duplicates, and that signal triggers embeddings.
  5. /ship is the only automatic path from facts into the wiki, and a person reviews it in the ship pull request.
