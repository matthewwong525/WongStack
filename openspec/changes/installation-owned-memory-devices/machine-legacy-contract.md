# Legacy history review and future cutover

This seven-new-path task4.2 slice prepares read-only source inspection and explicit operator review. It supplies no SQL15, provider runner, live transport, installation upgrade, import, machine admission or ready result. Task4.2 stays incomplete. A source test adapter returning valid readbacks does not mean an actual Worker, token or serving path has been closed. SQL1–14, their manifests, proof frames, original receipts and unexecuted snapshots remain unchanged.

`inspectLegacyMemory` accepts only a trusted in-process adapter, the exact resource target and at most20 selected fact/session/raw records in total. It checks release SQL digests and exact logical DDL, checks known FTS shadow names, and refuses foreign/gapped/partial/future layouts. Its release-file grammar is deliberately limited to the pinned migrations; it is not an SQL execution or general migration API. Each source row set, input, hash input and returned projection is bounded to128KiB. Historical authority table inspection also refuses more than1000 rows per table. Large installations need a separately reviewed paginated extension, never silent truncation.

Supported inspection layouts are genuine1–6, completed10/11 and completed14. SQL7–9 without a completed bootstrap and intermediate12/13 require a separate explicit upgrade contract. Legacy1–6 has no stable installation/repository IDs: the result preserves that absence rather than inventing continuity. Completed10/11 verifies exact resource IDs/origins, original configuration/bootstrap/audit and11 manifest linkage, ordinary configuration pin revision1, pending/ready state, ownership-attempt completion and consumed-review linkage. Existing removals, bindings, membership revisions and prior evidence enter the history commitment; they are never made active. A repinned or unverifiable old bootstrap refuses pending its own historical evidence review. Completed14 additionally requires the real branded trusted runtime context and its independently validated baseline, data receipts and deployment pins. Ordinary machine/data-admin contexts cannot supply that authority.

Facts commit all original columns and exact tag definitions/links. Sessions commit their original attribution, timestamps, cursor and raw address; a selected fact with a session requires that exact session in the selection. A raw object requires exactly one selected nonprivate session, the original address, bounded content hash and exact byte count. Selected modern captured facts are refused by this legacy operation. The output contains IDs, counts and hashes, with original raw paths retained as historical provenance; an email appearing in an old path grants no authority. Fact bodies, authors, labels, raw transcript content, credentials and provider response envelopes do not enter the review output. Private user/feedback visibility stays private even if an old shared flag is set.

`reviewLegacyMemory` binds a retained frozen inventory to an explicit decision, selected evidence and destination installation/repository/machine/grant/key commitment, revisions, credential generation and scope. Unknown fields, matching-email or label evidence, foreign targets, omitted/duplicated/changed records and mismatched independently inspected destination evidence refuse. Existing10/11/14 IDs must remain identical. Reader destinations cannot turn historic shared work into reader publication. Unmapped records remain admin-only. The review hash is a nonsecret intent, never an import completion or access grant.

Resource authority is distinct from current resource existence. An original creation projection names the exact account/database, original POST creation path and retained receipt hash. GET cannot replace POST. Explicit reviewed adoption instead names a separate decision, operator authority, actual ownership readback, exact backup and private evidence reference; it remains labelled adoption and does not fabricate original creation or fresh12 history. Missing or unverifiable evidence refuses. The adapter must verify the original retained artifact or explicit reviewed adoption before supplying its resource-ownership commitment; accepting an arbitrary user-supplied digest is unsupported.

## Trusted adapter obligations

The modules call only `read`, `readMigration`, `inspectSource`, `inspectRaw`, `inspectDestination` and optional `inspectClosure`. There is no credential loader, arbitrary execution callback, command dispatch or default adapter. These are capabilities of an independently authorized trusted operator process, never HTTP input or machine data-admin permissions. Raw callback failures become fixed safe `MemoryOperatorError` codes without provider messages, causes or envelopes; only explicitly listed existing safe refusal codes survive, recreated without the original error object. An arbitrary string passed to the shared error constructor is normalized. The new fixtures implement these capabilities using disposable historical SQL and synthetic private evidence. Actual provider transport remains separately coordinated.

`read` must execute only the module's finite read statements against the exact authorized memory database and return faithful bounded results. `inspectSource` must independently verify actual resource ownership, the retained exact backup artifact and the complete legacy authority/serving inventory. Its observation is at most120seconds old and cannot be in the future. This recency bound is not a transaction guarantee: sequential REST reads may race. The eventual15 mutation must independently revalidate every selected row/tag/session/raw hash, original source/history/backup, closure observation, destination commitment and grant revisions after closure and again before writing.

`inspectRaw` must read and hash the original object bytes, verify the exact account/bucket/key and byte count, and retain private readback evidence. A supplied hash string, email prefix, shared summary or guessed source path does not prove raw ownership. `inspectDestination` must verify the exact reviewed destination reservation or genuine current grant/key possession from its own retained operator evidence. Equality with a caller's JSON is insufficient. An unmaterialized destination reservation permits only review preparation; the15 final receipt must require the genuine current consumed grant and same proven persistent key, without changing the reviewed tuple.

`inspectSource` must enumerate all Workers able to reach the memory D1/R2, canonical/alias domains and zone routes, active deployments, retained versions, preview/version origins and direct-client/service/device/key credentials. Each exact endpoint/method and credential identity is retained, including intended route-disabled or reviewed-handler closure and exact replacement source hash. Unavailable account/zone/version enumeration or an unidentifiable credential refuses. Listing only the current two Workers or one token class cannot certify complete closure.

The exact memory bucket also requires independent public-access and public-origin inventory: R2 public/r2.dev/custom-domain access can bypass Workers and retired provider tokens. Closure must read back public access disabled and every reviewed public origin closed, with paginated origin evidence and exact anonymous GET refusal probes. No bucket is represented explicitly by null. Never infer privacy from a legacy default. Unknown external serving access blocks; unrelated business buckets/services are outside the authorized retirement.

`inspectClosure` must obtain actual readbacks from exhaustive paginated enumerations and retain every page/count/next-page/critical-response digest. Projected worker/version/route/credential IDs must cover the reviewed inventory exactly; an added path needs a new review. It must read actual disabled-route state or the reviewed exact replacement handler source with legacy serving denied, plus retirement of every exact former credential. The callback must verify those semantics before returning them; opaque hashes alone are not proof. It must perform denied probes for every exact endpoint/method and every formerly usable credential identity plus anonymous access. A class sample, random invalid credential, redirected response or a200 containing an empty body is insufficient. Secret request material stays private; request/response hashes and the actual401/403/404 refusal enter the projection. Every readback/probe must bind the same independently observed revision and target, and the observation must still be fresh.

Provider and service credentials use actual token revocation or reviewed shared-token replacement; database-key removal cannot stand in for provider retirement. Shared-token replacement must preserve the reviewed business/CI permission commitment. When the provider cannot exclude memory resources from a broad token, require a reviewed replacement arrangement before retiring the old client token; unsupported scoped retirement remains blocked. Never revoke an unrelated business or CI token merely because it can manage the account. Trusted installation operator credentials remain a separate management capability, never ordinary memory access.

Every retired direct-provider credential also requires an actual denied direct-memory API probe status and retained private probe evidence. A token failing on a Worker route does not establish denied direct D1/R2 access. The adapter must probe both configured memory resources and commit that exact joint result; a missing or still usable target cannot produce the direct-memory denial projection.
