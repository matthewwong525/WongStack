# Machine runtime source contracts

This task3.0 source layer is separate from the exact gated schema12 preparation. It exposes no Worker dispatch, CLI, capture hook, client, R2 transport or provider runner. No source check or returned receipt proves production readiness. All results remain version2 `pending-setup` or `blocked`, with the original installation/repository and canonical app/memory origins; a later core must prove a permitted operation for the initiating machine before returning ready.

## Stores and receipts

`machineRuntimeMigrations` pins all thirteen SQL files. It preserves grants, revoked tombstones, credential hashes and authored history. Completed10/11, uncompleted12, gaps, missing structures, foreign/future tables and ambiguous receipts refuse. A partially applied13 upgrade never automatically repairs or relabels a baseline.

The upgrade stores the exact original12 expected snapshot for fresh retries. Its new baseline digest commits the retained12 bootstrap/manifest/audit and target. Runtime attempts commit target, baseline, pins, auth/pin/runtime revisions, expected snapshot, exact payload, request hash and a unique audit identity. Runtime and schema12 maintenance barriers are mutually guarded: issue/enroll/revoke nest the retained12 mutation in one exact13 attempt. Only independently outcome-checked audit/completion receipts reopen the barrier. A provider or D1 success envelope cannot complete an operation. Nontransactional partial mutations stay closed; a losing identical attempt cannot borrow another attempt's audit identity. Lost responses recover only an exact current outcome and never revive removed authority.

## Context and activation authority

`trustedMachineRuntimeContext` verifies actual trusted provider resource/deployment/origin readbacks. Its branded provider context can prepare, issue, revoke and activate. `publicMachineContext(D1, pinnedInstallation)` has only the supplied ordinary D1 binding; it cannot create provider/readMigration capabilities or dispatch those privileged operations. The context is an internal in-process capability, never an HTTP input or public result. A fabricated plain context is refused. Ordinary memory admin data scope never changes authority.

`activateMachineRuntime` is an uncalled trusted source primitive with an append-only activation attempt/receipt. It accepts exact protocol and route-contract hashes, current target/pins/baseline and revisions, and requires every legacy key/admin/credential/device/identity/membership/provider/bootstrap authority table to be empty. Legacy cutover evidence and adoption are unsupported until task4.2; no historical rows are cleared here. Additive SQL13 guards then refuse retained legacy Worker INSERT/UPDATE into `memory_keys` and `memory_admins`, including a partial activation receipt, without changing SQL0001–0012. Inactive13 retains meaningful legacy fixtures. Activation cannot reopen or delete its retirement receipt.

Before exposing a public D1 context, the later core must compare the activation protocol/route hashes against its own exact supported constants and validate production deployment, canonical origin, path, method and resource pins. An arbitrary trusted digest record is not proof an arbitrary Worker implements that contract. Public mutation and bearer primitives require the durable activation receipt; activation itself still returns pending. No activation caller or live invocation ships in this slice.

## Possession and renewal

All machine signatures use WebCrypto P-256/SHA-256. Public-only canonical JWK coordinates are exactly32 decoded bytes with canonical base64url encoding; private/unknown fields and other algorithms/curves refuse. The signing-key commitment is the SHA-256 of the canonical public JWK. A digest, public JWK or service JWT alone is not possession proof.

The signed frame binds version/algorithm, distinct purpose, exact canonical POST/path/origin, installation/repository/machine/grant/attempt, target hash, expected snapshot, all critical operation values, nonce and a deadline of at most120 seconds. The server recomputes this frame from its validated context. Enrollment also checks the raw unexpired one-use capability against the stored hash and key commitment before consuming the grant. Mutation nonce hashes are append-only and globally unique; raw capabilities, signatures, private keys and bearer tokens never enter receipt payloads or public results.

`renewRuntimeMachine` accepts a fresh proof from the same active consumed grant after bearer expiry without a human step. It keeps the stable namespace/scope and appends a hash-only generation. Only the newest credential and its immediate predecessor within an overlap of at most120 seconds can authenticate; older generations never return. Revocation, removed generic principal, changed grant/machine revision or maintenance immediately blocks every generation and renewal. Reader scope includes own private capture and shared reads, with no shared publication or authority change.

An already-consumed12 machine whose commitment really commits a P-256 public key can establish its first13 key/rotation using fresh private signing proof and its exact original12 credential/completion receipt. It retains its namespace/grant and does not reenroll. A synthetic/non-signing commitment, revoked grant or unverifiable legacy claim fails closed; no label/email inference or human-admission substitute is used.

## Self refresh and response loss

`readSignedMachineSnapshot` uses a distinct signed `self-status` POST purpose. It verifies the current active consumed grant and persistent commitment without requiring a fresh bearer or current client revision, then returns only that machine's sanitized current snapshot and latest exact completed credential hash/generation/attempt/expiry. This lets the client discover its locally precommitted candidate after response loss, proof expiry and an unrelated machine operation. It issues no credential and never exposes a directory or another machine's metadata. Revocation still refuses it.

`readSignedEnrollmentSnapshot` similarly requires a distinct `enrollment-status` proof, raw unexpired pending capability and matching signing commitment. It refreshes only that candidate's snapshot without consuming the grant; consumed/revoked/expired capabilities refuse. Neither read exposes revisions anonymously. These strictly read-only status proofs do not write nonce receipts: replay within their short signed120-second window may return the same proven machine's current metadata. Their distinct purpose cannot authorize any mutation. Mutation proofs remain single-use and require a fresh exact snapshot.

## Transcript quarantine and privacy

`stageRuntimeTranscript` records only object/session/content hashes, exact owner/grant/machine revision and credential generation. `publishRuntimeTranscript` needs a durable exact stage receipt, fresh purpose-bound proof/current snapshot and the same live owner/grant/machine generation. Another machine's unrelated auth revision change does not reassign or strand the capture; own credential rotation/revocation quarantines it. Publication checks the current outcome independently before appending its receipt. No R2 upload, download or publication caller is implemented.

The ledger's `shared` label describes summary provenance only. Raw bytes remain owner-private, with existing explicit data-admin visibility; shared-read members never inherit another machine's raw transcript. `readRuntimeTranscriptOwner` requires a current machine-bound bearer and durable published receipt, then returns only hashes to a future transport. An expired historic proof does not erase a retained stage/publication receipt or grant raw access. Runtime source tests exercise two genuinely enrolled machines, reader shared refusal, unrelated-machine publication, own generation changes, revocation and private raw authorization.
