Go through the verbs

/explore → /plan → /apply → /save → /ship, for every request.

Details

Actor: agent. Action: explores, then asks a question round before it plans. Result: an errand gets the same ceremony as a code change.

  1. The classification is the only new step. It needs no new file or install field, so every repo gets the same behavior and grows from what it is used for.
  2. Only plain requests skip the verbs. Code is still planned, reviewed, and shipped. What a plain request teaches goes to the wiki, as the knowledge flow shows.

The wiki shape every repo can grow. Setup seeds none of the new sections; each appears when the first fact needs it.

Hub
  • wiki/README.md scope is now repeatable knowledge, not only process; links each section when it appears 1
People · grows from use
  • wiki/people/README.md who is who; created by the first fact about a person
  • wiki/people/<name>.md one per person: git emails, how they like work done 2
Topic pages · grow from use
  • wiki/<topic>.md how we do X, the product, customers, recurring tasks; created when first needed 3
Development
  • wiki/development/ process pages stay; memory, the change loop, and required tools get edits
  • wiki/development/home.md home as the machine's recorded personal repo, cross-repo memory, private-fact routing, browser logins 4
  1. The test for a wiki page: will this help with a future task that is not this one? A one-time detail stays in memory or in the change.
  2. The agent finds the current person by git config user.email. When no page lists that email, it writes a short page. A page can list more than one email.
  3. One person's preference goes on their page. A rule for everyone goes on a topic page. Different preferences are both kept, each on its own page. Private life goes in home only.
  4. The format is the same in every repo. Home is only the repo the machine record names; its wiki has no other shape.
