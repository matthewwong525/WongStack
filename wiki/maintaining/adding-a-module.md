# Adding a module

A module is a part of WongStack that any repo can add alone, with one pasted message, such as [memory](../../.agents/plugins/memory/README.md) or [the browser](../../.agents/plugins/browser/README.md). This page owns the rules a module follows; memory is the example for each. A module is still a payload part, so a change to it is [a release](../../.agents/rules/payload.md), and a skill inside it follows [adding a skill](adding-a-skill.md).

## Where it lives

- **One folder per module, in the source:** `.agents/plugins/<name>/`, beside the others. Nothing else goes in `.agents/plugins/`.
- **In the source, each skill folder is a link into it:** `.agents/skills/<name> → ../plugins/<name>`, such as `.agents/skills/daily → ../plugins/daily`. Claude Code then loads it from the checkout, and a branch runs its own code. A Markdown link names the real `.agents/plugins/<name>/…` path, by [repo layout](repo-layout.md#linking).
- **In every install, it is a real folder** at `.agents/skills/<name>/`. The [payload inventory](../../.agents/skills/wong-sync/references/payload-files.json)'s `mapped` entry sends the source folder there, and the sync writes each shipped link into the folder at that path. The installed modules are the module folders in the skills folder: keep no list of them, and no list of what each needs.
- **A module is one folder, and its other commands sit inside it in `skills/<command>/`.** With `.claude-plugin/plugin.json`, the host loads the folder as a plugin, so a nested command is named `/<module>:<command>`: Daily's `/daily:schedule`, and the browser's hidden `hand-over` and `shop`. The module's one `mapped` entry ships `skills/` inside it. Don't put a command in a sibling folder to keep its bare name: the module is then several folders, and a copy of one folder loses the rest.
- **A module with no hooks may map each command to its own folder** to keep its bare name: one `mapped` entry per `skills/<command>/`, and the longest entry wins over the module's. Only the commands link into `.agents/skills/`, never the module folder, or each command loads twice. [The build loop](../../.agents/plugins/loop/README.md) is the one example: its eight commands keep their names, and its own files install at `.agents/skills/loop/`.
- **The repo's own parts stay outside the folder:** its profile, its server part, and its settings. Memory's are in [`.agents/memory/`](../../.agents/memory/profile.mjs), the loop's in [`.agents/loop/`](../../.agents/loop/profile.mjs), Daily's in [`.agents/daily/`](../../.agents/daily/profile.mjs), and the browser's in [`.agents/browser/`](../../.agents/browser/profile.mjs). An update can then replace the folder and lose nothing.

## What the folder holds

- **Its hooks**, in `hooks/`, named by its `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json`; never in the repo's shared settings files, so a copy of the folder brings them. Codex reads the module from the root `.claude-plugin/marketplace.json`, one entry per module at `./.agents/skills/<name>`, and [`codex-plugin.mjs`](../../.agents/skills/wong-sync/scripts/codex-plugin.mjs) installs each entry.
- **A README that leads with the paste-in install message**, then the update message: one line a person pastes into any AI tool, naming the module's setup guide by its GitHub address. See [memory's README](../../.agents/plugins/memory/README.md).
- **A setup guide that works from GitHub** in a repo with nothing installed. It stops in a full WongStack install, copies the folder in, looks at the repo and fills each gap, asks before each step that costs money or makes something public, ends with the module's check, commits, and asks before any push. Its `## Update` section three-way merges the folder from its recorded version. See [memory's setup guide](../../.agents/plugins/memory/references/setup.md).
- **A start-of-chat check that asks first, once per chat.** When the repo lacks a part, the module's start hook has the AI ask whether to set it up, and never starts setup on its own. A resumed chat stays quiet. A module that works with every slot empty, such as the loop or the browser, needs no check.

## What it may reach

- **Only its own folder.** A module imports no file outside it, so it runs in a repo that has nothing else. It reaches the repo only through a named slot that the repo fills, such as memory's [profile](../development/memory.md#the-profile), and works when an optional slot is empty.
- **No other module.** A module works without the others, and links no file in another module's folder: a module copied alone then has no link that goes nowhere. A guide that asks the person a question says how in one sentence, such as *ask in the chat as a multiple choice, with the assistant's question tool when it has one*. One that adds to another does so through that one's slot, filled from the project's own files, never by its setup changing the other module.
- **Its docs link only inside its own folder.** A relative Markdown link that leaves the module leads nowhere in a project without WongStack's wiki, so the step misses the rule it was sent to read. What a step needs lives in the module, and the wiki links down to it; a WongStack-only page takes its full `https://github.com/matthewwong525/WongStack/blob/main/…` address, by [repo layout](repo-layout.md#linking). [`module-install.test.mjs`](../../scripts/tests/module-install.test.mjs)'s *docs link nothing outside its own folder* test fails on each one and names it.
- **A server part ships `serve()`, a store check, and one slots object.** The project's route calls `serve(request)` and gives it the project's slots as one object, not a file per part. A store check that runs with `node --test` tells a new database it is ready. Memory's [store check](../../.agents/plugins/memory/store/contract.mjs) and Access's [slots](../../.agents/plugins/access/references/setup.md#6-write-the-slots) are the examples: a project with another database or sign-in fills the slots, and the module stays as shipped.

## Versions and checks

- **Each change to the folder raises the version** in both `plugin.json` files, and the two stay equal. A module with no hooks still has both files, with no `hooks` entry. The update finds its merge base by that version, so one version must mean one exact folder. [`check-module-versions.mjs`](../../scripts/check-module-versions.mjs), one of [the payload checks](../../scripts/payload-checks.mjs), fails when a module's folder differs from `main` and the version did not rise.
- **One test installs each module alone.** [`module-install.test.mjs`](../../scripts/tests/module-install.test.mjs) places each module's files in an empty repo by its `mapped` entries, writes a minimal profile, runs the module's check, and fails on an import or a relative docs link from outside the folder. For the browser, Daily and Access, it also fails on a Markdown link or WongStack GitHub address into another module's folder, and on a file installed outside the module's one folder.
