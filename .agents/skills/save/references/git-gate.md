# The git gate

The pull-request and CI runbook **`/save` performs for both ordinary checkpoints and `/ship`'s delegated shipping checkpoint**. `/ship` consumes the result instead of repeating these mechanics.

Everything below assumes a feature branch with commits already on it. `main` stands for the repo's default branch — **assume it**, since every repo `/wong-setup` creates is on `main` and `git symbolic-ref refs/remotes/origin/HEAD` fails on a freshly created one. Only where `main` doesn't exist, resolve the real name with `gh repo view --json defaultBranchRef --jq .defaultBranchRef.name`.

## 1 — open or update the pull request

```bash
gh pr view --json number,state,url 2>/dev/null
```

| PR state | Action |
|---|---|
| **OPEN** | `git push`, then regenerate the body (below) |
| **none** | `git push -u origin HEAD`, then `gh pr create` — HEREDOC body from the template, title in repo style |
| **MERGED** | the branch is already shipped — skip the CI wait, and say there's no live preview |
| **CLOSED** (not merged) | stop and ask whether to reopen or push to a fresh branch; never silently revive |

### The body is a mirror of the change, regenerated every time

The change file is the source of truth, so overwriting the body is safe by construction — reviewers comment on the PR, they don't edit the body. It is **generated, not curated**: never try to preserve manual body edits.

```markdown
## Summary

**Status:** <Status line from proposal.md>

<the proposal's Why / What Changes, condensed to a few readable lines>

## Tasks

<the tasks.md checklist verbatim, current checkbox state>

## Preview

[<PREVIEW_URL>](<PREVIEW_URL>)   ← omit this whole section if no preview URL was found

---
_Handoff: `openspec/changes/<name>/` — resume with `/continue <name>`. This body is regenerated by every `/save`; comment rather than editing it._
```

In shipping context the source is the explicit `openspec/changes/archive/YYYY-MM-DD-<name>/` and the footer links that archive without offering `/continue`; the active change no longer exists. `/ship` never writes or preserves a separate body — its delegated `/save` call regenerates this one whether the PR is new or existing.

## 2 — wait for checks, auto-fix on failure

The push above triggers CI where the repo has it.

```bash
ROOT="$(git rev-parse --show-toplevel)"
bash "$ROOT/.claude/skills/save/scripts/wait-for-checks.sh" 20
```

Read the final `RESULT:` line. Ordinary checkpoints may finish unverified because they merge nothing; ship-delegated checkpoints return a merge-safe result:

| Result | Meaning | ordinary `/save` | `/save --shipping` result consumed by `/ship` |
|---|---|---|---|
| **SUCCESS** | checks passed | continue | `SHIP_GATE_RESULT=SUCCESS` |
| **NONE** | no checks configured — PR review is the gate | continue | `SHIP_GATE_RESULT=NONE`; invoking `/ship` is the approval |
| **FAILURE** | checks failed | auto-fix loop below | auto-fix loop below; exhausted cap returns `SHIP_GATE_RESULT=FAILURE` |
| **TIMEOUT** | still running past the budget | report the PR link, don't block | `SHIP_GATE_RESULT=TIMEOUT`; do not merge |
| **UNKNOWN** | `gh` couldn't be asked | report as **unverified**, continue | `SHIP_GATE_RESULT=UNKNOWN`; do not merge |

**`UNKNOWN` is not `NONE`, ever.** One means the repo has no CI; the other means we failed to find out. The two callers diverge here for one reason: `/save` is a checkpoint and the branch isn't going anywhere, while merging on an unverified gate is exactly how a red branch reaches the default branch. Never report `UNKNOWN` as "no checks configured."

### The auto-fix loop

Read the failing log, fix, commit, push, re-wait:

```bash
RUN_ID=$(gh run list --branch "$(git rev-parse --abbrev-ref HEAD)" --limit 1 --json databaseId --jq '.[0].databaseId')
gh run view "$RUN_ID" --log-failed | tail -120
```

**Cap: 3 attempts.** Still red → stop with the error and the checks link. A CI failure is not a stop condition until the cap is reached — fixing and re-pushing *is* the runbook. Never bypass with `--no-verify` or `--force`.

This cap covers the CI fix-and-repush loop only. No caller runs a further retrying gate after it — `/walk` is invoked deliberately and carries no retry budget of its own.

## What each caller keeps

This runbook does **not** own, and each skill states for itself:

- **`/save`** — the preview-URL discovery, staging by path (never `git add .`), the prose fast path, the session note, and the OpenSpec sync.
- **`/ship`** — the default-branch-CI preflight, OpenSpec archive invocation, worktree-safe merge, and remote-branch deletion. The archive commit/push/PR/branch-CI checkpoint belongs to its delegated `/save` call.
- **`/walk`** — the staging walkthrough, which it runs after invoking `/save`; it gates nothing here.
